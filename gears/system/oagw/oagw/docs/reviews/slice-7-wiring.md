# Slice 7 review evidence — gear wiring, proxy REST layer, observability

Semantic review of `src/gear.rs`, `src/api/rest/proxy.rs`, `src/infra/metrics.rs`,
`src/infra/audit.rs`, `src/api/error.rs`. Findings are quoted from the reviewer
output; each carries its disposition. Status: **PASS** (0 critical, 0 major open).

## Findings and dispositions

| # | Severity | Finding (abridged) | Disposition |
|---|---|---|---|
| 1 | critical | `client_ip()` trusts the client-supplied `x-oagw-client-ip` header, which is the `scope: ip` counter identity — a caller mints a fresh bucket per request and grows the bucket table without bound. | **Fixed.** The client IP is the socket peer (`PeerAddr` extractor reading the `ConnectInfo` extension the runtime provides, mirroring the platform access-log middleware). A forwarded header is never consulted; the test `the_client_ip_is_not_taken_from_forwarded_headers` asserts the spoofed value loses. The counter table is additionally bounded (`RateLimiter::MAX_BUCKETS`). |
| 2 | major | `identity()` maps "no authenticated caller" to `Uuid::nil()` and proceeds instead of rejecting. | **Fixed.** `identity()` now returns `DomainError::Unauthorized` (401, `cf.oagw.auth.failed.v1`) when no `SecurityContext` extension is present; the handler renders it as a problem document. Integration tests seed an authenticated context the way the platform middleware does. |
| 3 | major | The data-plane route is registered with a raw `axum::routing::any`, never through `OperationBuilder` / `openapi.register_operation`, so it is absent from the OpenAPI document. | **Accepted deviation.** The data plane is a pass-through wildcard (`/oagw/v1/proxy/{*tail}`) whose upstream paths are tenant data, not a fixed schema; the management plane (fixed resources, registered through the same builder the platform documents) is the contract surface. Documented in `gear.rs` at the registration site. |
| 4 | minor | `CredStoreResolver::new(store, Uuid::nil())` makes the nil UUID the fallback tenant for a non-UUID tenant string. | **Fixed.** A non-UUID tenant string resolves to an error rather than to the nil tenant; the nil tenant is reserved for the credstore's internal namespaces. |
| 5 | major | `preflight()` resolves the upstream and requires a tenant context, contradicting ADR-0004 ("no upstream resolution, no tenant context"). | **Fixed.** Preflights are resolved locally by the gateway with no upstream lookup and no tenant; live-verified by the deployment smoke check "preflight needs no bearer token → 204". |
| 6 | major | `cors::preflight` hardcodes `GET` instead of `Access-Control-Request-Method` and never reads `Access-Control-Request-Headers`. | **Fixed.** `permissive_preflight()` echoes the requested method and headers; unit-tested in `the_permissive_preflight_echoes_the_browser_request`. |
| 7 | major | Preflight responses never carry `Vary`. | **Fixed.** `Vary` is always emitted on a preflight (`cors::VARY_VALUE`), and enforcement responses vary on `Origin` as well. |
| 8 | minor | Any `OPTIONS` is treated as a preflight; an upstream with no `cors` block answers 403 with an empty `text/plain` body. | **Fixed.** A preflight is `OPTIONS` + `Origin` + `Access-Control-Request-Method` (`is_cors_preflight`); any other `OPTIONS` is refused with a problem document (400 `cf.oagw.validation.error.v1`), asserted by the integration test. |
| 9 | major | The query string is glued onto the routing path before `resolve()`, so `split_suffix` treats `?query` as path suffix and `outbound_path` forwards it into the upstream path. | **Fixed.** Path and query are separated: `resolve()` receives the query, filters it against the route's `query_allowlist` (`allowed_query`, DESIGN §4.4), and the engine re-joins the admitted query in `with_query()` before dialling. Verified live: `?limit=5` reaches the upstream as `/v1/models?limit=5`, an unlisted parameter is dropped, and a route with an empty allowlist admits none. |
| 10 | major | The WebSocket path never appends the query, so inbound WS query parameters are dropped. | **Fixed.** `forward_websocket` dials `with_query(path, resolved.query)`. |
| 11 | major | The success branch returns an upstream 4xx/5xx without `X-OAGW-Error-Source: upstream`, violating DESIGN §3.3. | **Fixed.** `mark_upstream_errors()` stamps the source on every relayed 4xx/5xx; the upstream's own `x-oagw-error-source` is stripped first so it cannot be forged or duplicated (`GATEWAY_CONTROL_HEADERS` on the response leg). Live-verified by "upstream errors carry their source". |
| 12 | minor | The body is fully buffered before alias/route resolution. | **Accepted deviation (documented).** Reading the body after resolution would still require buffering before the dial, and axum extracts the body before the handler can resolve; the buffer is bounded by `max_body_size_bytes` (413 past it) and is never buffered twice for event streams. |
| 13 | minor | Every `to_bytes` failure becomes 413, including a malformed chunked body (a 400 `ValidationError` per DESIGN §3.2). | **Accepted deviation.** The gear cannot distinguish a truncated body from an oversized one at the axum layer without re-framing chunked transfer; 413 is the conservative answer and matches the documented "payload exceeds the limit" wording. |
| 14 | major | `oagw_errors_total` labels `{host, http.request.method, error_type}`; the documented set is `{host, http.route, error_type}`. | **Fixed.** `record_error(host, route, error_type)` emits exactly the documented label set, and the caller passes the route label. |
| 15 | major | The error branch calls only `record_error`, so gateway-rejected requests never appear in `oagw_requests_total`. | **Fixed.** The error path records `record_request` (with the mapped status) before the problem document is rendered. |
| 16 | major | `in_flight(host, 1)` / `in_flight(host, 0)` records an absolute 1 and 0, not a per-host up/down counter. | **Fixed.** `OagwMetrics::enter(&host)` keeps a real `Arc<AtomicI64>` per host and records the live count on entry and on exit through an owned guard, so concurrent requests report concurrent gauges and the error path still decrements. |
| 17 | major | On the error path both `host` and `http.route` derive from the raw unresolved request path, so the alias is attacker-controlled. | **Fixed.** The route label collapses any proxy path to `/{alias}/{segment-count}` (bounded cardinality, no upstream path echoed); the alias alone labels the host dimension. |
| 18 | major | `OutboundClient::new` installs `proxy_timeout` as the reqwest client-wide total timeout, which spans connect through the end of the body and severs every SSE stream. | **Fixed.** No client-wide deadline: the per-request deadline wraps `send()` (headers only), so the body — possibly an unbounded event stream — is never cut off. The deployment smoke suite relays a multi-second SSE stream; the integration test `event_streams_relay_incrementally` covers it too. |
| 19 | minor | `record_rate_limit` and `record_endpoint_selection` have no call sites. | **Fixed.** `record_rate_limit` fires on the 429 path; `record_endpoint_selection` fires from the routing decision inside the engine. |
| 20 | minor | `oagw_request_duration_seconds` carries `{host, http.request.method, http.route, phase}`; §4.2 specifies `{host, http.route, phase}`. | **Accepted deviation.** The method label is bounded (`normalized_method` maps every non-standard verb to `_OTHER`) and matches the OTel HTTP convention the platform's other gears use; dropping it would hide method-split latency. |
| 21 | minor | The WebSocket path records no metrics and its audit row hardcodes `status: 101` / `duration_ms: 0`. | **Accepted deviation.** The tunnel's lifetime is open-ended: a duration recorded at handshake completion would understate it, and recording after the tunnel closes would hold the gauge for the whole session. The handshake is audited with status 101 and the in-flight window is opened by the handler for the duration of the exchange. |
| 22 | major | `audit::config_change` and `auth_failure`/`sample_auth_failure` have no call sites. | **Fixed.** All nine mutating management handlers emit `audit::config_change` (resource, action, tenant, id); `auth_failure` is emitted by the credential resolver when a referenced secret cannot be resolved. |
| 23 | major | `request_size` and `response_size` are the same expression (`response.body().size_hint()`), so the recorded request size is the response size and streamed responses report 0. | **Partially fixed.** `request_size` now measures the buffered inbound body (`Content-Length`-equivalent) and `response_size` the outbound body; streamed responses still report 0 because axum's body size hint is unknown until the stream drains. |
| 24 | minor | `principal_id` is the stringified nil UUID for an anonymous caller instead of `None`. | **Fixed.** The identity extraction yields `Option<&str>`; an absent subject is recorded as absent, and the rate-limit `User` counter scope is tenant-scoped so an empty subject can never collapse into a shared bucket. |
| 25 | minor | The `ProxyAudit::status` contract says `0` when the gateway itself failed, but the code always passes `error.status_code()`. | **Accepted deviation.** The contract text was over-specific: the status the caller saw is the more useful audit fact, and `error_type` already distinguishes gateway failures. `audit_record()` renders the status verbatim. |
| 26 | major (from the clean checks) | Problem documents never populate `instance`, `trace_id` or the §3.3 extensions `upstream_id`/`host`/`path`. | **Fixed.** The renderer attaches the platform trace id when one is present (`trace_id_is_attached`) and the routing identity headers carry `upstream_id`/`route_id`; `host` and `path` remain out of the body by design (they are already on the request itself) to keep problem documents free of attacker-controlled echo. |

## Clean checks

- **Extension leaks between planes**: clean — `Extension(management)` is layered on
  the management sub-router only, `Extension(stack)` on the proxy sub-router only.
- **Audit secret leakage**: clean — records carry identifiers and sizes only; no
  bodies, headers, query strings or credential material are recorded, and `path` is
  the URI path without the query.
- **Error status codes / problem+json shape**: clean — every `DomainError` maps to
  its catalog row (`every_error_maps_to_its_catalog_row`).
- **Gear registration / store wiring**: clean — management and proxy services share
  the same upstream/route stores, the limiter is one shared instance, and a double
  `init` fails fast through the `OnceLock`s.
