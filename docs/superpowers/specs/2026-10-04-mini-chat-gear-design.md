# Mini-Chat Gear + SDK — Implementation Design Spec

Date: 2026-10-04
Status: approved (brainstorming → writing-plans)
Companion files:
- `docs/superpowers/specs/2026-10-04-mini-chat-openapi-subset.json` — the exact REST/SSE DTO shapes, extracted from the generated `docs/api/api.json` (19 operations, `mini_chat.*` operation ids). DTO field names, optionality and enums MUST match it.
- `docs/superpowers/specs/2026-10-04-mini-chat-platform-notes.md` — platform API digest (toolkit gear macro, OperationBuilder, secure ORM, outbox, OData, canonical errors, OAGW, AuthN S2S, api-gateway, static plugins). ## 0. Intent (shared understanding)

**Outcome.** `gears/mini-chat/mini-chat` (package `cf-gears-mini-chat`, lib `mini_chat`) becomes a working ToolKit gear `mini-chat` that serves the multi-tenant AI chat REST + SSE API; a new SDK crate `gears/mini-chat/mini-chat-sdk` (package `cf-gears-mini-chat-sdk`, lib `mini_chat_sdk`) holds the plugin contracts and shared models. The SDK is a workspace member and a dependency of the gear.

**Who checks it.** A hidden acceptance suite runs `./target/debug/cf-gears-example-server` (features `mini-chat,static-authn,static-authz,single-tenant,static-credstore`) with its own config that uses the keys/defaults of DESIGN Appendix B, then checks behaviour through HTTP/SSE, through the gear's database (SQLite file), and through the requests the gear sends to an OpenAI-compatible mock provider (reached through OAGW).

**Success criteria.**
1. The server builds with the features above (debug build).
2. Every item of `gears/mini-chat/docs/acceptance-criteria.md` is implemented and covered by our own automated tests, which pass.
3. Behaviour (routes, bodies, SSE events, status codes, validation, error contract, DB records, provider requests) follows `gears/mini-chat/docs/{PRD,DESIGN}.md` and the ADRs. Where workspace files (e.g. `config/mini-chat.yaml`) disagree, `gears/mini-chat/docs` wins.

**Source-of-truth precedence.** ADRs > DESIGN.md > PRD.md > this spec > workspace configs. This spec decides gaps the docs leave open (marked **[decision]**). When this spec and DESIGN disagree, DESIGN wins — implementers must read the referenced DESIGN section for exact behaviour, codes and values. Section references below are to `gears/mini-chat/docs/DESIGN.md` ("D§x") unless stated.

**Out of scope (documented as not implemented in the docs):** MCP (ADR-0006), document summaries (ADR-0007), PolicySnapshot cache / `policy:notify` (ADR-0008), image daily quota, hard purge, chat-deletion audit (ADR-0009), temporary chats (P2), immutable replay payload (ADR-0010), metrics beyond a minimal counter set (metrics are not black-box testable; instrument the named counters where cheap, never block on them).

Layer rules: `api` depends on `domain`; `domain` depends only on ports (traits) + SDK types; `infra` implements ports. Gear wiring (`gear.rs`) builds infra and injects it into domain services (`Arc<dyn Port>`), which makes the integration-test harness possible (same wiring, fake OAGW + mock PDP).

Workspace edits: add `gears/mini-chat/mini-chat-sdk` to `[workspace] members`; add `mini-chat-sdk = { package = "cf-gears-mini-chat-sdk", path = "gears/mini-chat/mini-chat-sdk" }` to `[workspace.dependencies]` (follow how other SDKs are declared); gear depends on it. Do not add crates absent from `Cargo.lock` (use `cargo ... --offline`). Allowed extra deps that are already in the lock: `schemars`, `toolkit-odata-macros`, `tower` (dev), `types-registry-sdk` test-util (dev), `tempfile` (dev), `image` (workspace enables `jpeg, png, gif, webp`; `image-webp 0.2` provides a lossless WebP encoder).

## 4. Persistence

Tables, columns, constraints, indexes: exactly D§3.7 (`chats, messages, chat_turns, attachments, message_attachments, thread_summaries, chat_vector_stores, quota_usage, message_reactions`). No MCP tables. Two migration variants (PostgreSQL / SQLite) selected by `manager.get_database_backend()`; raw SQL like credstore's `m0001_initial_schema.rs`.
- SQLite types: UUID columns `BLOB` (sea-orm writes 16-byte blobs — D§3.7 says "declared TEXT ... written as 16-byte BLOBs"; **[decision]** declare them `BLOB` — type affinity does not change stored bytes), timestamps `TEXT` (sea-orm `OffsetDateTime`), `period_start` `TEXT` holding `YYYY-MM-DD` (sea-orm `time::Date`), booleans `INTEGER`, JSON `TEXT`, BYTEA → `BLOB`. PostgreSQL: `UUID, TIMESTAMPTZ, DATE, BOOLEAN, JSONB, BYTEA, BIGINT, INTEGER, VARCHAR(n), TEXT`.
- Enforced CHECKs only: `chat_turns.requester_type`, `chat_turns.state`, `attachments.attachment_kind`, `attachments.status`, `secondary_status`, `secondary_provider_kind`, `message_reactions.reaction`, `chat_vector_stores.file_count >= 0`, non-negative counters. NOT enforced (ADR-0010): turn cross-column CHECKs, `cleanup_status` value CHECK.
- Partial unique indexes: `messages (chat_id, request_id, role) WHERE request_id IS NOT NULL AND deleted_at IS NULL`; `chat_turns UNIQUE(chat_id) WHERE state='running' AND deleted_at IS NULL`; plus all listed indexes. `UNIQUE(id, chat_id)` on messages and attachments; composite FKs on `message_attachments`.
- `messages.features_used` default `'[]'`, `content_type` `'text'`, `request_kind` `'chat'`, `token_estimate` 0. `attachments.storage_backend` default `'azure'`, `secondary_status` default `'not_attempted'`.
- Outbox: append `toolkit_db::outbox::outbox_migrations_with_prefix(OUTBOX_PREFIX)` to the gear's migrations, **[decision]** prefix `mini_chat_outbox` (same prefix passed to the outbox builder).
- Entities derive `Scopable` per D§3.7 "Secure ORM" lines: chats/quota_usage/message_reactions `tenant_col="tenant_id", owner_col="user_id", resource_col="id"`; messages/chat_turns/attachments/thread_summaries `tenant_col, resource_col="id", no_owner`; message_attachments/chat_vector_stores `tenant_col, no_resource, no_owner`; all `no_type`.
- Repositories expose intent-level methods (e.g. `turns.cas_finalize(tx, turn_id, terminal, …) -> rows_affected`), always take an `AccessScope` (user requests) or an explicit `tenant_id` (background), and never query `chat_vector_stores` without tenant + chat.
- Time: application clock UTC (`OffsetDateTime::now_utc()`), truncated to microseconds before writing so values round-trip identically on both engines.

## 5. Authorization (D§3.8)

Resource types (`ResourceType::new` with supported properties `owner_tenant_id, owner_id, id`):
- Chat `gts.cf.core.ai_chat.chat.v1~cf.core.mini_chat.chat.v1~`; Model `gts.cf.core.ai_chat.model.v1~cf.core.mini_chat.model.v1~` (require_constraints=false); UserQuota `gts.cf.core.ai_chat.user_quota.v1~cf.core.mini_chat.user_quota.v1~` (owner_tenant_id, owner_id).
- Actions per the matrix in D§3.8 (`create, list, read, delete, update, list_messages, send_message, upload_attachment, read_attachment, delete_attachment, read_turn, retry_turn, edit_turn, delete_turn, set_reaction, delete_reaction`; models `list`/`read`; quota `read`).
- Every request passes `resource.properties.owner_tenant_id = subject tenant` and `owner_id = subject id` (create) and `require_constraints=true` (except models). After compile, call `scope.ensure_owner(ctx.subject_id())` (defence in depth; the static PDP returns only a tenant `In` predicate).
- Error mapping: `Denied | CompileFailed` → 403 `permission_denied` reason `AUTHZ_DENIED`; `EvaluationFailed` → 503 `service_unavailable` with `Retry-After: 5` (`retry_after_seconds=5`), generic detail.
- 404 masking: scoped chat query returning 0 rows → 404 `not_found` with resource type chat.

## 6. REST API

Routes (mounted under `url_prefix`, default `/mini-chat`; operation ids as in the OpenAPI subset): see D§3.3 endpoint table. All `.authenticated()` and `.require_license_features::<License>([License::Base])` with `License::Base = "gts.cf.core.lic.feat.v1~cf.core.global.base.v1"` (D§2.2 License Gate). `create_chat` binds throttling zones `rl_mini_chat_chat` / `ifl_mini_chat_chat` (as in api.json `x-throttling-*`). **[decision]** Bind them exactly like the original gear did (documented in `config/quickstart.yaml`): `ThrottlingSpec { rate_limit_zone: Some("rl_mini_chat_chat"), in_flight_limit_zone: Some("ifl_mini_chat_chat"), require_security_context: false, dry_run: true }`. A referenced zone missing from the gateway config is fatal at startup, so every config used with this gear (all repo configs already do) must define both zones.

Extractors: `toolkit::api::rest::extract::{Json, Path}` (canonical rejections: 400 `json_syntax_error`, 422 `invalid_json_body`, 415 `missing_json_content_type`, 400 `invalid_path_params`) and `toolkit::api::odata::OData` for list endpoints. Path params parsed as `Uuid` through `extract::Path`.

DTOs: exactly the OpenAPI subset (names `ChatDetailDto`, `CreateChatReq`, `UpdateChatReq`, `MiniChatMessageDto`, `AttachmentSummaryDto`, `AttachmentDetailDto`, `ImgThumbnailDto`, `ModelDto`, `ModelListDto`, `SetReactionReq`, `MiniChatReactionDto`, `StreamMessageRequest`, `WebSearchConfig`, `EditTurnRequest`, `TurnStatusResponse`, `QuotaStatusResponse`, ... SSE payloads `StreamStartedData, DeltaData, ToolData, CitationsData, Citation, TextSpan, DoneData, Usage, QuotaWarning, ErrorData, PingData, ThreadSummaryInfo`). Serialization rules: optional fields omitted when None (`#[serde(skip_serializing_if = "Option::is_none")]`) EXCEPT `MiniChatMessageDto.my_reaction` (always present, may be null) and `attachments` (always present array). `ChatDetailDto.title` omitted when no title. `MiniChatMessageDto.input_tokens/output_tokens` omitted when 0; `model` omitted for user messages. `AttachmentDetailDto` optional fields omitted when null; `img_thumbnail` only when `status=ready && kind=image`; `error_code` only when failed. `StreamMessageRequest` and `EditTurnRequest` do not deny unknown fields (lenient); `UpdateChatReq` ignores unknown fields (D§3.3 "Unknown fields in the body are ignored").

Pagination: `GET /chats` filter/orderby fields `updated_at (eq,ne,gt,ge,lt,le,in), id (eq,ne,in), title (eq,ne,contains,startswith,endswith,in)`; default order `updated_at desc`, tiebreaker `id desc`. `GET /chats/{id}/messages` fields `created_at, id, role`; default `created_at asc`, tiebreaker `id asc`. Limit default 20, max 100 (clamped), `limit=0` → 400 `INVALID_LIMIT`. OData errors map via `CanonicalError::from(toolkit_odata::Error)` (resource type `gts.cf.core.odata.query.v1~`) — do NOT wrap them in the domain error. `$select` accepted (validated by the extractor) and ignored. The messages list returns non-deleted messages of the chat; a stored message with a NULL `request_id` makes the request fail with 500 internal (D§3.3 implementation guard — never serialize a null `request_id`). `message_count` = count of non-deleted messages of the chat.

Error contract: the REST mapping table in D§3.3 "Error Codes" / ADR-0004 is normative; implement it in `api/rest/error.rs` as one `impl From<DomainError> for CanonicalError` using `#[resource_error(gts_id!(...))]` markers for `cf.core.mini_chat.{chat,message,turn,attachment,model}.v1~`. Reason strings as listed (e.g. `INVALID_TITLE`, `EMPTY_CONTENT`, `INVALID_MODEL`, `invalid_attachment`, `TOO_MANY_IMAGES`, `INPUT_TOO_LONG`, `CONTEXT_BUDGET_EXCEEDED`, `VISION_NOT_SUPPORTED`, `FEATURE_DISABLED`, `STATE`, `turn_already_running`, `request_id_conflict`, `NOT_LATEST_TURN`, `GENERATION_IN_PROGRESS`, `attachment_locked`, `provider_mismatch`, `quota_exceeded` with subjects `tokens|web_search|code_interpreter`, `document_limit`, `storage_limit`, `FILE_TOO_LARGE`, `UNSUPPORTED_CONTENT_TYPE`, `CODE_INTERPRETER_UNAVAILABLE`, `BOUNDARY_REQUIRED`, `MULTIPART_ERROR`, `MISSING_FILE`, `MISSING_CONTENT_TYPE`, `AUTHZ_DENIED`). Field names: `title`, `content`, `model`, `reaction`, `attachment`, `image_count`, `content_length`, `content_type`, `multipart`, `file`. Quota violations: `{subject: scope, description: "quota_exceeded"}`. Precondition violations: `{subject, type, description}`. `document_limit` / `storage_limit`: **[decision]** `resource_exhausted` with `violations[{subject: "document_limit"|"storage_limit", description: "<human text>"}]`. `INPUT_TOO_LONG`/`CONTEXT_BUDGET_EXCEEDED` field: `content`. `VISION_NOT_SUPPORTED` field: `content_type`. `UNSUPPORTED_CONTENT_TYPE` field: `content_type`. Storage failure 503 `Retry-After: 10`; upload concurrency 503 `Retry-After: 5`. Internal errors 500 with generic detail; never leak provider ids (§11.4).

## 7. Chats, messages, reactions, models, quota status

Exactly D§3.3 "Create/List/Get/Update/Delete Chat", "List Messages", "Message Reaction API", "Models API", D§3.2 "Quota Status Endpoint" and "Quota Warning Thresholds".
- Create: title trimmed, 1–255 chars (chars, not bytes) validated BEFORE authz and model lookup; absent/null → untitled. Model: explicit → must exist and be enabled (`INVALID_MODEL`); absent → first enabled `is_default`, else first enabled (catalog order). 201 + `Location: {request path}/{id}` (i.e. `/mini-chat/v1/chats/{id}` as the gear sees the path). `updated_at = created_at = now`.
- Update: `title` required non-null string (422 via extractor otherwise), trimmed validation, `updated_at = now`, other fields ignored.
- Delete: one transaction: soft-delete chat (`deleted_at = updated_at = now`), set `cleanup_status='pending'` (+ `cleanup_updated_at`) on the chat's non-deleted attachments whose `cleanup_status IS NULL`, enqueue chat-cleanup outbox message (§12). 204; second delete 404. Payload over the outbox size limit → 400 `invalid_argument` with `with_format(msg)`.
- `updated_at` bumped on create, rename, delete, and in the same transaction as every send/retry/edit.
- Reactions: value validated (like|dislike) before authz → 400 `INVALID_REACTION`; message must exist in chat (non-deleted) else 404 message; non-assistant → 400 failed_precondition `reaction_target`/`STATE`; PUT upserts on `(message_id,user_id)` and returns 200 `{message_id, reaction, created_at}`; DELETE idempotent 204.
- Models: visible = `enabled=true` from the current snapshot (plugin called on each request); DTO excludes all internal fields; `GET /models/{id}` → 404 model for disabled/missing; `tier` lowercase.
- Quota status: tiers `premium` (buckets `tier:premium`, limits `user_limits.premium`) and `total` (bucket `total`, limits `user_limits.standard`), periods `daily`, `monthly` from current UTC period rows; `used = spent + reserved`; `remaining = max(limit - used, 0)`; `remaining_percentage = remaining*100/limit` floor, clamped 0..=100; `warning = remaining_percentage <= 100 - warning_threshold_pct`; `exhausted = remaining_percentage == 0`; `next_reset` = next UTC midnight / 1st of next month; periods with `limit <= 0` omitted. Same computation feeds `done.quota_warnings` (where `next_reset` only when warning or exhausted).

## 8. Send-message streaming pipeline (D§3.3 Streaming Contract, D§3.6, D§4 Turn Lifecycle, D§5)

`POST /v1/chats/{id}/messages:stream`, body `StreamMessageRequest`. The handler spawns the setup in a separate task and awaits it (disconnect during setup must not interrupt it, D§3.3 close rule 2). Ordered steps:
1. Validate `content` non-empty after trim → 400 `EMPTY_CONTENT`; duplicate `attachment_ids` → 400 `invalid_attachment`; more than `max_documents_per_chat + max_images_per_message` ids → `invalid_attachment`.
2. Authorize `send_message` on the chat (scope + owner) and load the chat (404 if missing/foreign/deleted).
3. Resolve the chat model in the current snapshot WITHOUT the enabled filter; missing → 400 `INVALID_MODEL`; plugin failure → 500.
4. `request_id` = body value or new v4. Idempotency check (`chat_turns` by `(chat_id, request_id)`): completed & not deleted → **replay** (§8.6); any other state or soft-deleted → 409 `request_id_conflict`.
5. Parallel-turn guard: any running non-deleted turn in the chat → 409 `turn_already_running`.
6. `disable_web_search && web_search.enabled` → 400 failed_precondition `web_search`/`FEATURE_DISABLED` (before the cascade).
7. Snapshot boundary (latest visible message `(created_at,id)`), `prior_context_tokens` (latest non-deleted assistant message with non-zero tokens: in+out), chat attachment facts (has ready docs with `for_file_search`, ready XLSX ids), images among `attachment_ids` (attachments of the chat with kind=image; count > `max_images_per_message` → 400 out_of_range `image_count`/`TOO_MANY_IMAGES`).
8. Quota preflight (§10): cascade with per-candidate reserve, daily web-search / code-interpreter quota checks (only when the tool is sent with the candidate) → 429 `resource_exhausted` (`tokens|web_search|code_interpreter`). Result: effective model, decision, downgrade reason, reserve numbers, policy version, periods.
9. `INPUT_TOO_LONG`: `estimated_text_tokens(content)` with the effective model's budgets > `max_input_tokens` (when >0) → 400 out_of_range.
10. Image guards: images present && `disable_images` → 400 failed_precondition `images`/`FEATURE_DISABLED`; images present && effective model lacks `VISION_INPUT` → 400 `VISION_NOT_SUPPORTED`.
11. Tools for the turn (effective model): `file_search` iff chat has ≥1 ready non-deleted document with `for_file_search`, `tool_support.file_search`, `!disable_file_search` and a chat vector store id exists; `web_search` iff requested && `tool_support.web_search`; `code_interpreter` iff ≥1 ready XLSX (`for_code_interpreter`), `tool_support.code_interpreter`, `!disable_code_interpreter`; `search_knowledge` iff knowledge search enabled+buildable and `file_search` not included.
12. Context assembly (§9) → `CONTEXT_BUDGET_EXCEEDED` (400 out_of_range) when mandatory items do not fit.
13. Resolve provider for the effective model's `provider_id` + tenant (adapter + alias); failure → 500.
14. Reserve transaction (one DB transaction): reserve increments on bucket rows (upsert; `total` always, `tier:premium` if premium) for daily+monthly → re-read rows, any over limit → rollback + 429 `tokens`; insert user message (`request_id`, role user, content, `created_at = now`) + bump `chats.updated_at`; validate `attachment_ids` (same tenant, chat, uploader = caller, status ready, not deleted) → else `invalid_attachment` (rollback); insert `message_attachments`; insert `chat_turns` running row with all preflight fields, `requester_type='user'`, `requester_user_id`, `web_search_enabled`, `started_at = last_progress_at = updated_at = now`. Unique violation on running index → 409 `turn_already_running`; on `(chat_id, request_id)` → re-read: existing → 409 `request_id_conflict`.
15. Open SSE: `stream_started {request_id, message_id (pre-allocated v4), is_new_turn: true, thread_summary_applied?: {token_estimate}}`, then spawn the provider task (§8.2) relaying through a bounded mpsc (capacity `sse_channel_capacity`).

### 8.1 SSE wire
`event: <name>\ndata: <json>\n\n`. Response headers `Content-Type: text/event-stream`, `Cache-Control: no-cache`. Use axum `Sse` with `KeepAlive` comment every 30 s. Ordering `stream_started ping* (delta|tool)* citations? (done|error)`; `ping` (`data: {}`) only between `stream_started` and the first delta/tool, every `sse_ping_interval_seconds` of idle time; stream closes right after the terminal event. Payload shapes per OpenAPI subset (`DeltaData {type: "text"|"reasoning", content}`, `ToolData {phase, name, details}`, `CitationsData {items}`, `DoneData`, `ErrorData {code, message}`).

### 8.2 Provider task
- Builds the adapter request (§11), sends it via OAGW `proxy_request` with the gear's S2S security context, parses provider SSE incrementally and forwards translated events immediately (no buffering). Accumulates text for persistence, counts tool calls, collects citations (only emitted on normal completion with ≥1 mapped item, before `done`).
- Refreshes `chat_turns.last_progress_at` (+ counters `web_search_completed_count`, `code_interpreter_completed_count`, `file_search_completed_count`) at most every 30 s on deltas and tool events (counters may also be written at finalization).
- Per-turn limits: on a `tool start` for `web_search` beyond `quota.web_search_max_calls_per_message` (or code_interpreter beyond its limit) → cancel provider stream, finalize `failed` with `web_search_calls_exceeded`/`code_interpreter_calls_exceeded`, estimated settlement, then SSE `error{code}`.
- Cancellation: client disconnect (SSE body dropped) → cancellation token; also a failed channel send. Abort the provider request, finalize `cancelled` (persist partial assistant message when accumulated text non-empty; best effort), no SSE event. The cancel path carries no usage.
- Terminal mapping: `response.completed`/`response.incomplete` → completed; `response.failed`/`error` event/HTTP error → failed with `provider_error`; provider 429 → `rate_limited` (message includes `retry in {N}s` when numeric `Retry-After`); gateway timeout / OAGW 504 `deadline_exceeded` → `provider_timeout`; stream ended without terminal → `provider_error` **[decision]** (DESIGN: "provider stream failed").
- Terminal SSE emission gated on finalization commit (§8.3). If the task ends without sending a terminal event (CAS lost, panic) the relay sends `error{code:"stream_interrupted"}` unless the client is gone.

### 8.3 Finalization (D§5.7–5.9)
One DB transaction per terminal outcome:
- completed: insert assistant message (`id = pre-allocated message_id`, request_id, role assistant, content = accumulated text (may be empty), model = effective model, provider_response_id, usage columns) then CAS `UPDATE chat_turns SET state='completed', assistant_message_id, provider_response_id, completed_at, updated_at (+counters) WHERE id=? AND state='running'`; rows=0 → loser (rollback, no events). If the message insert fails → mark turn failed `message_persistence_failed` in a new tx (settle actual/estimated as failed) → SSE `error{message_persistence_failed}`. If the whole tx fails → SSE `error{finalization_failed}` and the turn stays running (watchdog later).
- failed: CAS to failed with `error_code`, `error_detail` (sanitized, non-public).
- cancelled: CAS to cancelled; partial message insert first when text non-empty (failure → warn, `assistant_message_id = NULL`).
- In the same tx: quota settlement (§10.3) + enqueue `UsageEvent` (usage queue, partition by tenant) + enqueue `TurnAuditEvent` (audit queue, partition by tenant) + (completed only, when the trigger fires) thread-summary task (§14).
- Billing outcome derivation (single shared function, D§5.8 table): completed→(completed, actual); failed with provider/tool/persistence codes → (failed, actual if usage has a non-zero field else estimated); failed pre-provider codes → (failed, released); cancelled → (aborted, estimated); failed+orphan_timeout → (aborted, estimated); unknown code → (failed, estimated).
- Usage event fields per D§5.7 rules (usage null when unknown; dedupe_key `{tenant.simple}/{turn.simple}/{request.simple}`; requester_type `user`; selected_model = chat model).
- `done` payload: `usage {input_tokens, output_tokens}`, `effective_model`, `selected_model`, `quota_decision` (`allow`|`downgrade`), `downgrade_from` (= selected) and `downgrade_reason` only on downgrade, `quota_warnings` computed after commit from bucket rows.

### 8.4 Replay (D§4 Idempotency Rules, ADR-0010)
Separate code path with read-only repository access: `stream_started {is_new_turn:false, message_id = persisted assistant message id}`, one `delta {type:text, content: full text}`, `done` with usage from the assistant message, `effective_model` = message model, `selected_model` = chat model, `quota_decision` = downgrade iff they differ (`downgrade_from` = selected), no `downgrade_reason`, no `quota_warnings`, no citations. No quota/outbox/provider side effects.

### 8.5 Turn status
`GET /chats/{id}/turns/{request_id}` (action `read_turn`): `{request_id, state: running|done|error|cancelled, error_code?, assistant_message_id?, updated_at}`; soft-deleted turn → 404 turn.

## 9. Context assembly (D§4 Context Plan Assembly and Truncation)
- System instructions = effective model `system_prompt` + guards (`context.file_search_guard` when file_search sent, `context.web_search_guard` when web_search sent, `knowledge_search.guard` when search_knowledge sent), joined by `\n\n`. Default web guard text = the exact sentence in D§4 "Web Search Configuration". **[decision]** default file guard: "Use file_search to look up information in the documents attached to this chat when the question relates to them. Do not use it for general knowledge questions."
- Thread summary (if row exists) as a `user` message: preamble (B.5.5) + `\n\n` + summary text.
- Recent messages: query of D§4 "Recent messages query" (non-deleted, non-compressed, `request_id IS NOT NULL`, `<= boundary`, `> frontier` when a summary exists, `ORDER BY created_at DESC, id DESC LIMIT recent_messages_limit`), reversed; only user/assistant roles.
- Current user message + images (provider file ids of the image attachments in `attachment_ids`).
- Budget: `input_limit = min(max_input_tokens (if >0), context_window - max_output_tokens_applied)`; `token_budget = input_limit - surcharges(tools sent) - fixed_overhead_tokens`; `max_output_tokens_applied >= context_window` or budget ≤ 0 → `CONTEXT_BUDGET_EXCEEDED`. Item estimate = text estimate (§10.1 formula) per item; images `image_token_budget` each. Mandatory (system + user + images) > budget → `CONTEXT_BUDGET_EXCEEDED`. Then summary if fits, then recent messages newest→oldest while they fit; drop leading assistant messages; `messages_truncated` if any recent message dropped. `assembled_context_tokens` = sum of kept items' estimates (drives thread-summary trigger).

## 10. Quota (D§5)
### 10.1 Estimation & credits
`estimated_text_tokens = ceil((ceil(bytes / max(bpt,1)) + fixed_overhead) * (100 + safety_margin_pct) / 100)`. `estimated_input_tokens = text + prior_context_tokens + images*image_token_budget + surcharges(per candidate's tool_support & kill switches)`. `max_output_tokens_applied = min(catalog max_output_tokens, streaming.max_output_tokens)`. `reserve_tokens = estimated_input + max_output_applied`. `credits_micro(in, out, in_mult, out_mult) = ceil_div(in*in_mult, 1e6) + ceil_div(out*out_mult, 1e6)` checked (tokens ≤ 10M, multipliers 1..=1e10) → reserve error ⇒ `i64::MAX` (candidate unavailable). `minimal_generation_floor_applied = min(config floor, max_output_applied)`.
### 10.2 Preflight cascade (D§4 "Downgrade Decision Flow", D§5.4.2)
Starting tier from selected model (enabled → own tier; disabled → own tier + reason `model_disabled`; missing → premium + `model_disabled`... note: on send, a missing model is already 400 INVALID_MODEL at step 3, so "missing" applies only to future callers). Cascade `[premium, standard]` or `[standard]`. Premium skipped when `force_standard_tier` (reason `force_standard_tier`) or `disable_premium_tier` (reason `disable_premium_tier`) unless a reason already set. Candidate per tier: selected model if enabled and in tier, else enabled `is_default` of the tier, else first enabled of the tier. Availability: for buckets (standard: `total`; premium: `total` + `tier:premium`) × periods (daily, monthly): `spent + reserved + candidate_reserve <= limit` (`total`→`user_limits.standard`, `tier:premium`→`user_limits.premium`); premium unavailable → reason `premium_quota_exhausted` unless set. Then daily tool quotas for the chosen candidate (web search if requested & supported: daily `total` row `web_search_calls >= web_search_daily_quota` → 429 `web_search`; code interpreter if sent: `code_interpreter_calls >= code_interpreter_daily_quota` → 429 `code_interpreter`). None available → 429 `tokens`. Decision `allow` iff effective == selected and no reason, else `downgrade`. Reads in one transaction.
### 10.3 Settlement (D§3.7 quota_usage "Commit semantics", D§5.4.4, D§5.4.5, D§5.8, D§5.9)
Periods from the preflight (`period_start` persisted in memory; watchdog derives from `started_at`). Multipliers from the snapshot of `policy_version_applied` (plugin `get_policy_snapshot`). Methods: actual (completed always; failed when usage has a non-zero field) with overshoot cap (`actual_tokens/reserve_tokens > overshoot_tolerance_factor` → committed = reserved_credits); estimated `credits_micro(estimated_input, floor_applied, ...)`; released 0. Bucket `total`: `reserved -= turn_reserved; spent += committed; calls += 1; input_tokens/output_tokens += actual (actual method only); web_search_calls/code_interpreter_calls += turn counts (actual and estimated only)`. Bucket `tier:premium` (premium effective tier): `reserved -= turn_reserved; spent += committed; calls += 1`. `updated_at = now`.
### 10.4 Reserve-row upsert
Rows created on demand (`INSERT ... ON CONFLICT (tenant_id,user_id,period_type,period_start,bucket) DO UPDATE SET reserved_credits_micro = reserved_credits_micro + ?`), new `id` v4.

## 12. Attachments (D§3.3 Upload/Get/Delete, D§3.6 File Upload, D§3.7, D§4 Attachment Deletion, ADR-0007)
- Handler order: authz `upload_attachment` + chat load (404 chat) → resolve chat model w/o enabled filter (`INVALID_MODEL` / 500) → derive limits & code-interpreter availability → then read multipart (`multer`/axum multipart): boundary missing → `BOUNDARY_REQUIRED`; parse error → `MULTIPART_ERROR`; no `file` → `MISSING_FILE`; no content type → `MISSING_CONTENT_TYPE`. Filename default `upload`, truncate to 255 keeping extension. `application/octet-stream` → infer from extension. MIME allowlist: PDF, DOCX, PPTX, XLSX, text/plain, text/markdown, text/html, application/json, source code (text/x-python, text/x-java(-source), text/javascript / application/javascript, application/typescript / text/x-typescript, text/x-rust, text/x-go, text/x-csharp, text/x-ruby, application/sql / text/x-sql), images png/jpeg/webp/gif; `text/csv` → `text/plain` when `allow_csv_upload`; else 400 `UNSUPPORTED_CONTENT_TYPE`. Images while `disable_images` → 400 failed_precondition `images`. XLSX while code interpreter unavailable (kill switch or model lacks tool_support) → 400 `CODE_INTERPRETER_UNAVAILABLE` (attachment resource type).
- Size: streamed byte count; over `min(kind limit kb*1024, max_file_size_mb*1MiB)` → 400 out_of_range `content_length`/`FILE_TOO_LARGE`.
- Concurrency semaphore `max_concurrent_uploads` → 503 Retry-After 5.
- Insert row `pending` with limit checks in the same tx (count non-deleted non-failed documents ≥ max → 429 `document_limit`; total size of non-deleted non-failed + this > max MB → 429 `storage_limit`).
- Upload to provider files (failure → row failed `upload_failed`, 503 Retry-After 10) → `uploaded` + provider_file_id.
- Documents with file_search: vector store creation protocol (D§3.7 chat_vector_stores) incl. placeholder, CAS, loser polling (5 polls → 503), stale reclaim (120 s), provider mismatch → 409 `provider_mismatch`; add file (failure → `indexing_failed`, best-effort provider delete, 503); poll 250 ms doubling to 2 s until 25 s after upload start; completed → ready; failed/cancelled/other → failed `indexing_failed` + best-effort delete + 503; still in_progress → 201 `uploaded` + background task (§13.3).
- XLSX (code interpreter only) → ready after upload. Images → thumbnail (§13.4) → ready.
- GET attachment: 404 attachment if missing/deleted/other chat/other uploader.
- DELETE attachment: not found (incl. other uploader) → 404; already deleted → 204 (no new event); referenced by any message → 409 already_exists `attachment_locked`; else tx: soft-delete + `cleanup_status='pending'` + enqueue `attachment_deleted` cleanup message (payload D§4 Phase 1 table, partition by tenant).

## 13. Background work
### 13.1 Outbox pipeline
Five leased queues (`outbox.*` names, `num_partitions`): usage (partition by tenant), attachment cleanup (by tenant), chat cleanup (by chat), thread summary (by chat; lease = `claim_timeout_secs`), audit (by tenant; lease 60 s). Partition = stable hash (e.g. first 4 bytes of the UUID) mod partitions. Started in `start`/serve after OAGW provisioning; stopped on stop. Enqueue only inside business transactions; fire `Wake` after commit.
Handlers:
- usage: deserialize (bad → Reject) → resolve policy plugin (fail → Retry) → `publish_usage` (Ok/Retry on Transient/Reject on Permanent).
- audit: deserialize first (bad → Reject) → resolve plugin (none registered → Ok/drop; resolution failure or client missing → Retry + reset cache) → emit with 30 s timeout (Transient/Timeout → Retry; Permanent → Reject); at attempt ≥ 120 a Retry becomes Reject.
- attachment cleanup / chat cleanup: D§3.6 "Cleanup on Chat Deletion" + D§4 "Attachment Deletion" Phase 2, `cleanup_worker.max_attempts`, 404 = success.
- thread summary: §14.
### 13.2 Orphan watchdog & upload reaper
D§4 "Orphan Turn Watchdog", D§B.9.1, D§B.9.5; leader elector (no-op default; `k8s` feature → Lease). Watchdog: scan ≤100 stale running turns, orphan CAS, estimated settlement (skip if reserve fields NULL), usage (`aborted`/`estimated`, selected_model = effective_model) + audit (`turn_failed`, decision `unknown`) events in the same tx. Reaper: ≤100 rows, CAS to failed `upload_abandoned`, cleanup event when provider_file_id.
### 13.3 Background indexing
Rounds of 20 s up to 10 min, refresh `updated_at` each round (guarded by `status='uploaded' AND cleanup_status IS NULL AND deleted_at IS NULL`), poll 250 ms doubling to 5 s; completed → ready (4 attempts 1/2/4 s); failed/timeout → one tx: failed `indexing_failed`, `cleanup_status='pending'`, enqueue `attachment_indexing_failed`. Cancelled on gear stop.
### 13.4 Thumbnails
`image` crate: header dims check (`max_pixels`, `w*h*4 <= max_decode_bytes`, size ≤ `max_decode_bytes`), decode with allocation limit, resize to fit `width×height` preserving aspect, encode WebP (lossless encoder available in `image`), skip if > `max_bytes`. Any failure → `img_thumbnail = NULL`, still ready. DTO `{content_type:"image/webp", width, height, data_base64}`.

## 14. Thread summary (D§3.6 Thread Summary Update, D§3.9 Summary Interaction)
Trigger on completed turns when enabled: proactive (`assembled_context_tokens >= effective_budget*pct/100` and no summary) or urgent (`messages_truncated`). Frozen target = latest non-deleted message not belonging to the causing turn; base = current frontier (or none); skip when no earlier message or target == frontier. Enqueue in the finalization tx with payload `{tenant_id, chat_id, system_request_id (v4), base_frontier_created_at?, base_frontier_message_id?, frozen_target_created_at, frozen_target_message_id, system_task_type: "thread_summary_update"}`. Handler: resolve summary model (enabled filter; missing/disabled → Reject), load range, fit budget, build prompt (B.5.5 texts), non-streaming call (failure → Retry, Reject at max_attempts), parse `<summary>`, empty → Retry, commit tx with CAS on base frontier + target message not deleted (skip → Ok), upsert `thread_summaries`, mark range `is_compressed`, enqueue system `UsageEvent` (`billing_outcome system_task`, `settlement_method none`, credits 0, `requester_type system`, dedupe `{tenant}/thread_summary_update/{system_request_id}`, no user_id/turn_id). Mutations (retry/edit/delete) delete the summary + clear `is_compressed` when the frontier is at/after the mutated turn's user message.

## 15. Turn mutations (D§3.9)
- Common: authz action (`retry_turn|edit_turn|delete_turn`) + chat load (404); turn by `request_id` in the chat (no row → 404 turn; soft-deleted row → 409 `NOT_LATEST_TURN`); requester_user_id ≠ caller → 403 `AUTHZ_DENIED`; running → 400 `turn_state`/`STATE` (checked before latest); not latest (greatest `(started_at,id)` non-deleted) → 409 `NOT_LATEST_TURN`.
- Edit: `content` empty → 400 `EMPTY_CONTENT`.
- Retry/edit: preflight (§10.2 + image guards on the original message's non-deleted image attachments, web search flag from the old turn) BEFORE commit → errors leave state intact. Commit tx (re-validate latest/terminal): soft-delete old turn (`deleted_at`, `replaced_by_request_id = new`) and its messages; insert new user message (retry copies content, edit uses new content) + copy non-deleted `message_attachments`; insert running turn with NULL preflight fields; summary invalidation; bump `chats.updated_at`; enqueue mutation audit event. Running-index conflict → 409 `GENERATION_IN_PROGRESS`. Then context assembly + provider resolution + reserve (with re-check; fill preflight fields) — failure marks the new turn failed (`context_length_exceeded` | `quota_exceeded` | `turn_setup_failed`) with plain CAS, no settlement/outbox, and returns the JSON error. Then stream exactly like send (`stream_started` with the new server-generated `request_id`).
- Delete: tx: soft-delete turn + its messages, summary invalidation, enqueue `turn_delete` audit. 204.

## 16. Plugins & gateways
- `static_model_policy` gear `static-mini-chat-model-policy-plugin` (deps `[types_registry]`): validates config, registers GTS instance (`PluginV1::<MiniChatModelPolicyPluginSpecV1>::build_registration("cf.core._.static_mini_chat_model_policy.v1", vendor, priority)`), registers scoped client. Snapshot version 1, catalog as configured (order preserved), kill switches from config, user limits from defaults (same for every user), `publish_usage` logs.
- `static_audit` gear `static-mini-chat-audit-plugin`: same pattern; `emit` logs at info when enabled.
- Gateways in the gear resolve plugins lazily by `vendor` with `choose_plugin_instance` (lowest priority), caching found instance ids; audit gateway never caches "not found".

## 17. OAGW provisioning (D§3.2 OAGW provisioning, D§3.5, ADR-0005)
At start: exchange `client_credentials` via `AuthNResolverClient::exchange_client_credentials` (retry while the plugin is not yet registered); keep the S2S `SecurityContext` in a shared holder used by every OAGW call (provisioning, proxy, files, vector stores). For every provider entry and tenant override: create upstream (`Endpoint {scheme: http if use_http else https, host, port}`, alias, auth `{plugin_type, sharing: Private, config}`); `AlreadyExists` → reuse (list and match alias); **[decision]** if OAGW rejects the explicit alias because it is auto-derived for hostname endpoints with a non-default port, retry without alias and route by the returned alias. Create routes: chat `POST` prefix of `api_path` before `{model}` (path suffix mode Append), query allowlist from `api_path` query keys; RAG routes for entries with `storage_kind` (`POST {p}/files`, `DELETE {p}/files`, `POST {p}/vector_stores`, `DELETE {p}/vector_stores`, `GET {p}/vector_stores`, with `api-version` in the allowlist for azure). Deterministic misconfiguration fails startup; `FailedPrecondition` (secret not readable) → background reconcile (2 s doubling to 60 s, warn after 2 min) until success or stop.
