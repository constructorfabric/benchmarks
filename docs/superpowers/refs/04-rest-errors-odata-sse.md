# 04 — REST routes, canonical errors (RFC 9457), OData, SSE on the api-gateway

Reference for implementing the `mini-chat` gear's REST + SSE API (`/mini-chat/v1/...`) on top of
`libs/toolkit`, `libs/toolkit-canonical-errors(-macro)`, `libs/toolkit-odata(-macros)`,
`libs/toolkit-db` (OData pagination) and `gears/system/api-gateway`.
Everything here was read from the code at the repo snapshot. Where repo docs disagree with code
(they do in several places, see §8), **the code wins**.

The current `gears/mini-chat/mini-chat/src/lib.rs` is an empty skeleton. Its `Cargo.toml` already
pulls `axum` (features `macros`, `multipart`), `multer = "3.1"`, `utoipa`, `toolkit`,
`toolkit-canonical-errors` (feature `axum`), `toolkit-gts`, `gts`, `toolkit-db` (`sqlite`,`pg`),
`toolkit-db-macros`, `toolkit-security`, `toolkit-macros`, `toolkit-odata` (feature `with-utoipa`).
It does not pull `toolkit-odata-macros` (needed for `#[derive(ODataFilterable)]`, see §3.3) or `tower`
(needed in dev-deps for `ServiceExt::oneshot`, see §6).

The full contract for each operation (operationId, tags, params, bodies, responses, headers, `$ref`s
resolved) is in `/tmp/refs/05-mini-chat-openapi.md`. It was generated by
`/tmp/refs/extract_mini_chat_openapi.py`.

## 0. Key facts

| Topic | Fact (file) |
|---|---|
| Route registration | `toolkit::api::OperationBuilder` (`libs/toolkit/src/api/operation_builder.rs`). `.register(router, openapi)` calls `router.route(&spec.path, method_router)`. The path is the **full** path, including the gear prefix: `"/mini-chat/v1/chats"`. |
| Where routes are registered | `impl toolkit::RestApiCapability for <Gear> { fn register_rest(&self, ctx:&GearCtx, router: axum::Router, openapi:&dyn OpenApiRegistry) -> anyhow::Result<axum::Router> }`. The gear attribute needs `capabilities = [..., rest, ...]`. |
| Auth | `.authenticated()` or `.anonymous()` is mandatory (typestate). `authenticated` adds `security: [{bearerAuth: []}]` to the OpenAPI operation. The gateway inserts `toolkit_security::SecurityContext` as a request extension, and the handler reads it with `Extension(ctx): Extension<SecurityContext>`. |
| License | Mandatory after `.authenticated()`. Use `.require_license_features([&License])` with `License: LicenseFeature` whose `as_ref()` returns `CORE_GLOBAL_BASE_LICENSE_FEATURE` (`gts.cf.core.lic.feat.v1~cf.core.global.base.v1`), or `.require_license_features::<License>([])`, or `.no_license_required()`. `.anonymous()` sets the license state too. |
| Throttling zones | `.with_throttling(ThrottlingSpec { rate_limit_zone: Some("rl_mini_chat_chat".into()), in_flight_limit_zone: Some("ifl_mini_chat_chat".into()), require_security_context: false, dry_run: false })`. | JSON body extractor | `toolkit::api::rest::extract::Json<T>`, also reachable as `extract::Json` through `toolkit::api::canonical_prelude::*`. Rejections: 400 `json_syntax_error`, 422 `invalid_json_body`, 415 `missing_json_content_type`, 413 `json_body_read_error`. All use `field: "body"` and `context.resource_type = gts.cf.core.http.request.v1~`. |
| Path / Query extractors | `extract::Path<T>` rejects with 400 `invalid_path_params` (`field: "path"`). `extract::Query<T>` rejects with 400 `invalid_query_string` (`field: "query"`). |
| Errors | Return `CanonicalError` (`toolkit_canonical_errors::CanonicalError`). `ApiResult<T> = Result<T, CanonicalError>` (`toolkit::api::canonical_prelude`). Declare resource types with `#[resource_error(gts_id!("cf.core.mini_chat.chat.v1~"))] pub struct ChatResource;`. |
| Problem JSON | `{type:"gts://gts.cf.core.errors.err.v1~cf.core.err.<category>.v1~", title, status, detail, instance, trace_id, context:{resource_type?, resource_name?, ...category fields}}`. Content type `application/problem+json`. `instance` and `trace_id` are filled by `toolkit::api::canonical_error_middleware` (installed by the gateway). |
| Retry-After | Set automatically **only** for `service_unavailable` (from `context.retry_after_seconds`). The gateway throttler also sets it on its own 429s. For your own `resource_exhausted` 429s you must add the header by hand. |
| OData | `toolkit::api::odata::OData` extractor (`OData(query): OData`) produces a `toolkit_odata::ODataQuery`. Paginate with `toolkit_db::odata::paginate_odata::<FilterField, Mapper, _, _, _, _>(select, conn, &query, ("id", SortDir::Desc), LimitCfg{default, max}, map)`. The result is `toolkit_odata::Page<T>`, serialized as `{items:[...], page_info:{next_cursor, prev_cursor, limit}}`. |
| OData error resource type | `gts.cf.core.odata.query.v1~` (`toolkit_odata::errors::OdataError`). This covers extractor errors and pagination-time errors. |
| SSE | `axum::response::sse::{Sse, Event, KeepAlive}`. OpenAPI: `.sse_json::<T>(openapi, desc)` gives `200 text/event-stream`. The toolkit helper `toolkit::SseBroadcaster<T>` is broadcast-based. |
| Compression | **None.** There is no `CompressionLayer` anywhere in gears/libs/apps. The gateway does not buffer 2xx bodies: `access_log` wraps the body in a streaming `CountingBody`, and `canonical_error_middleware` only touches error statuses. |
| 30 s timeout | `tower` `.timeout(Duration::from_secs(30))` on the whole gateway router, mapped to 504 `deadline_exceeded` ("Request exceeded 30s timeout"). | Tests | `Router` from your `register_routes(Router::new(), &OpenApiRegistryImpl::new(), svc)`. Insert `SecurityContext` into `req.extensions_mut()`. Call `tower::ServiceExt::oneshot`. Optionally add `.layer(axum::middleware::from_fn(toolkit::api::canonical_error_middleware))` to also get `instance`/`trace_id`. |

## 1. Registering REST routes

### 1.1 Gear wiring (pattern from `gears/credstore/credstore/src/gear.rs`)

```rust
use toolkit::{Gear, GearCtx, RestApiCapability};
use toolkit::api::OpenApiRegistry;

#[toolkit::gear(
    name = "credstore",
    deps = [authz_resolver, tenant_resolver, types_registry],
    capabilities = [system, db, rest, stateful],
    lifecycle(entry = "serve", stop_timeout = "30s", await_ready)
)]
pub struct CredStoreGear { service: OnceLock<Arc<Service>> }

impl RestApiCapability for CredStoreGear {
    fn register_rest(
        &self,
        _ctx: &GearCtx,
        router: axum::Router,
        openapi: &dyn OpenApiRegistry,
    ) -> anyhow::Result<axum::Router> {
        let svc = self.service.get().cloned()
            .ok_or_else(|| anyhow::anyhow!("credstore Service not initialized"))?;   // built in init()
        Ok(crate::api::rest::register_routes(router, openapi, svc))
    }
}
```

`RestApiCapability` is defined in `libs/toolkit/src/contracts.rs:52`. The `Router` is `axum::Router<()>`.
Dependency injection is done with `router.layer(axum::Extension(svc))`, applied **once after** all
routes (credstore `routes.rs` last line; types-registry `router.layer(Extension(service)).layer(Extension(registry))`).

### 1.2 `OperationBuilder` API (exact, `libs/toolkit/src/api/operation_builder.rs`)

Imports:

```rust
use toolkit::api::{OpenApiRegistry, OperationBuilder, ParamSpec, ResponseHeaderSpec,
                   ResponseHeaderType, ThrottlingSpec};
use toolkit::api::operation_builder::{
    CORE_GLOBAL_BASE_LICENSE_FEATURE, LicenseFeature, OperationBuilderODataExt,
};
```

Generic signature: `OperationBuilder<H = Missing, R = Missing, S = (), A = AuthNotSet, L = LicenseNotSet>`.
`register()` exists only on `OperationBuilder<Present, Present, S, AuthSet, LicenseSet>`, so a route
without a handler, a response, an auth choice, or a license choice is a **compile error**.

| Stage | Methods (signature summary) |
|---|---|
| Constructors | `get(path)`, `post(path)`, `put(path)`, `delete(path)`, `patch(path)`, `new(Method, path)`. The path uses axum 0.8 syntax `{id}` (same as OpenAPI). `{*rest}` wildcard → `{rest}` in OpenAPI. |
| Descriptive (any stage) | `.operation_id(&str)`, `.summary(&str)`, `.description(&str)`, `.tag(&str)` (repeatable), `.param(ParamSpec)`, `.path_param(name, desc)`, `.query_param(name, required: bool, desc)`, `.query_param_typed(name, required, desc, "integer")`, `.query_param_array(name, required, desc, item_type)`, `.query_params_from::<T: toolkit_contract::query::QueryParams>()`, `.with_throttling(ThrottlingSpec)`, `.exposed()` |
| Request body (any stage) | `.json_request::<T>(openapi, desc)` (T: `ToSchema + PartialSchema + RequestApiDto`; required=true; auto-registers schema), `.json_request_no_desc::<T>(openapi)`, `.json_request_schema(name, desc)`, `.json_request_schema_no_desc(name)`, `.request_optional()`, `.multipart_file_request(field_name: &str, description: Option<&str>)` (also sets allowed content types `["multipart/form-data"]`), `.octet_stream_request(Option<&str>)` (also sets `["application/octet-stream"]`), `.allow_content_types(&[&'static str])` |
| Auth (`AuthNotSet` → `AuthSet`) | `.authenticated()` → keeps L. `.anonymous()` → also sets `LicenseSet`. Deprecated: `.public()` = `.anonymous().exposed()`. |
| License (only on `AuthSet, LicenseNotSet`, i.e. **after** `.authenticated()`) | `.require_license_features<F: LicenseFeature>(impl IntoIterator<Item = F>)`, `.no_license_required()` |
| Handler (`Missing` → `Present`) | `.handler(h)` where `h: axum::handler::Handler<T, S> + Clone + Send + 'static`. Alternatively `.method_router(MethodRouter<S>)` for route-level layers. |
| First response (`R=Missing` → `Present`) | `.response(ResponseSpec)`, `.json_response(StatusCode, desc)` (no schema), `.no_content_response(StatusCode, desc)` (content_type ""), `.json_response_with_schema::<T>(openapi, StatusCode, desc)` (T: `ResponseApiDto`), `.json_array_response_with_schema::<T>(openapi, StatusCode, desc)` (inline `{type:array, items:{$ref:T}}`), `.text_response(StatusCode, desc, content_type)`, `.html_response(..)`, `.problem_response(openapi, StatusCode, desc)`, `.sse_json::<T>(openapi, desc)` (200 `text/event-stream`, `$ref` T), `.multipart_json::<T>(openapi, desc)` (200 `multipart/mixed`) |
| More responses (`R=Present`) | Same methods (they upsert by `(status, content_type)`), plus `.response_header(ResponseHeaderSpec)` (attaches to the **last** declared response; panics on duplicate name), `.standard_errors(openapi)`, `.with_400_validation_error(openapi)`, `.error_400/401/403/404/409/413/415/422/429/500/502/503/504(openapi)` |
| OData (trait `OperationBuilderODataExt`, any stage) | `.with_odata_filter::<F: FilterField>()` (adds `$filter` param + `x-odata-filter`), `.with_odata_select()` (adds `$select`), `.with_odata_orderby::<F>()` (adds `$orderby` + `x-odata-orderby`) |
| Final | `.register(router: Router<S>, openapi: &dyn OpenApiRegistry) -> Router<S>` |

`standard_errors()` declares exactly **400, 401, 403, 404, 409, 429, 500** as `application/problem+json`
with `$ref Problem`. It does **not** declare 422. Note that the docs claim it does; the code does not.

`ResponseHeaderSpec::new(name, description, ResponseHeaderType::{String|Integer|Boolean})`, and
`ResponseHeaderSpec::without_description(name, type)`.

`ParamSpec::path(n)`, `::query(n)`, `::header(n)`, `::cookie(n)`, then `.required(bool).description(..).param_type("integer").format("int64").minimum(1.0).array(bool)`.

`OperationSpec` fields (what the gateway reads): `method, path, operation_id, summary, description, tags,
params, request_body, responses, handler_id, authenticated, exposed, throttling, allowed_request_content_types,
vendor_extensions, license_requirement`.

Typestate ordering that compiles (credstore, types-registry, oagw all use one of these):

```rust
OperationBuilder::post("/mini-chat/v1/chats")
    .operation_id("mini_chat.create_chat")      // descriptive: any position
    .summary("Create a new chat")
    .tag("Mini Chat Chats")
    .authenticated()                             // AuthNotSet -> AuthSet
    .require_license_features([&License])        // only valid right after/any time once AuthSet & LicenseNotSet
    .with_throttling(/* ... */)
    .json_request::<CreateChatReq>(openapi, "Chat creation data")
    .handler(handlers::create_chat)              // Missing -> Present
    .json_response_with_schema::<ChatDetailDto>(openapi, StatusCode::CREATED, "Created chat")
    .response_header(ResponseHeaderSpec::new("Location", "Path of the created chat", ResponseHeaderType::String))
    .error_400(openapi).error_401(openapi).error_403(openapi).error_422(openapi).error_500(openapi)
    .error_503(openapi)
    .response_header(ResponseHeaderSpec::new("Retry-After", "Seconds to wait before retrying", ResponseHeaderType::Integer))
    .register(router, openapi)
```

This reproduces the exact `api.json` entry for `mini_chat.create_chat`: 201 + `Location` header,
problem responses 400/401/403/422/500/503, 503 + `Retry-After` header, and the
`x-throttling-*` extensions. Every mini-chat operation declares `Retry-After` on 503 this way. None of them
declares `Retry-After` on 429 (see the 05 file).

### 1.3 Auth axis and visibility axis

* `spec.authenticated` feeds the gateway route policy (`gears/system/api-gateway/src/gear.rs`
  `build_route_policy_from_specs`). Authenticated routes need a valid bearer, otherwise the response is 401:
  `CanonicalError::unauthenticated().with_reason("MISSING_BEARER" | "AUTHN_FAILED")` plus
  `WWW-Authenticate: Bearer ...` (`middleware/auth.rs`). Anonymous routes get `SecurityContext::anonymous()`
  inserted when no bearer is sent. Routes registered **without** `OperationBuilder` (raw `router.route`)
  fall back to `require_auth_by_default` (default `true`).
* `auth_disabled: true` (config/mini-chat.yaml) makes the gateway insert a fixed context
  `SecurityContext::builder().subject_id(DEFAULT_SUBJECT_ID).subject_tenant_id(DEFAULT_TENANT_ID)`
  (`toolkit_security::constants`: tenant `00000000-df51-5b42-9538-d2b56b7ee953`, subject `11111111-6a88-4768-9dfc-6bcd5187d9ed`).
* `.exposed()` only adds the vendor extension `x-toolkit-visibility: "exposed"`, which the OoP
  `GatewayProvider` reverse-proxy reads. In-process gears served by api-gateway do not need it.
  credstore and the published mini-chat api.json do not use it.

### 1.4 License requirement (base license feature)

```rust
// gears/system/types-registry/types-registry/src/api/rest/routes.rs
use toolkit::api::operation_builder::{CORE_GLOBAL_BASE_LICENSE_FEATURE, LicenseFeature};

struct License;
impl AsRef<str> for License {
    fn as_ref(&self) -> &'static str { CORE_GLOBAL_BASE_LICENSE_FEATURE }  // gts.cf.core.lic.feat.v1~cf.core.global.base.v1
}
impl LicenseFeature for License {}
```

`CORE_GLOBAL_BASE_LICENSE_FEATURE: &str = gts_id!("cf.core.lic.feat.v1~cf.core.global.base.v1")`
(`operation_builder.rs`). The two call forms behave differently:

* `.require_license_features([&License])` stores `license_requirement = Some([base])`. The gateway
  `license_validation_middleware` (`gears/system/api-gateway/src/middleware/license_validation.rs`)
  passes when every required name equals the base feature. Any other name gets
  403 `permission_denied` with `context.reason = "LICENSE_FEATURE_REQUIRED"` and
  `resource_type = gts.cf.core.api_gateway.route.v1~`. This is a stub: it is not a real license
  plugin call yet.
* `.require_license_features::<License>([])` (empty list) stores `None`. This is equivalent to
  `.no_license_required()` at runtime, and it is what types-registry, oagw and the docs use.

To *declare* the base feature, as the mini-chat ADR expects ("Tenant lacks the required license feature →
403 LICENSE_FEATURE_REQUIRED"), use the non-empty form `[&License]`.

### 1.5 Rate-limit / in-flight zones (how a route references a zone)

Code side (`toolkit::api::ThrottlingSpec`, `operation_builder.rs`):

```rust
#[derive(Clone, Debug, Default)]
pub struct ThrottlingSpec {
    pub rate_limit_zone: Option<String>,      // name in gateway `rate_limit_zones`
    pub in_flight_limit_zone: Option<String>, // name in gateway `in_flight_limit_zones`
    pub require_security_context: bool,       // false: throttled BEFORE auth (IP-keyed zones only)
    pub dry_run: bool,                        // observe only, warn-log, never reject
}

OperationBuilder::post("/mini-chat/v1/chats")
    // ...
    .with_throttling(ThrottlingSpec {
        rate_limit_zone: Some("rl_mini_chat_chat".to_owned()),
        in_flight_limit_zone: Some("ifl_mini_chat_chat".to_owned()),
        require_security_context: false,   // zones in config are `key: { type: ip }`
        dry_run: false,
    })
```

Config side (`config/mini-chat.yaml`, `quickstart.yaml` and `e2e-local.yaml` all define these):

```yaml
gears:
  api-gateway:
    config:
      rate_limit_zones:
        rl_mini_chat_chat: { rate_limit: 10/s, burst_limit: 10, response_status_code: 429,
                             response_retry_after: auto, key: { type: ip }, max_keys: 10000 }
      in_flight_limit_zones:
        ifl_mini_chat_chat: { in_flight_limit: 100, backlog_limit: 0, backlog_timeout: 0s,
                              response_status_code: 429, key: { type: ip }, max_keys: 10000 }
```

Behaviour (`gears/system/api-gateway/src/middleware/throttling.rs`, `config.rs`):

* At router build, `config.validate_throttling()` and `build_maps(&specs, &config)` run. An operation that
  references an undefined zone fails startup with
  `"throttling: operation POST /mini-chat/v1/chats references undefined rate_limit zone '...'"`.
  `key.type: identity` zones need `require_security_context: true`, an `.authenticated()` op, and
  `auth_disabled = false`.
* `require_security_context=false` → pre-auth map (layered outside auth). `true` → post-auth map, where the
  identity key is `SecurityContext::subject_id()`.
* Rejection (`throttle_response`): `ApiGatewayGatewayError::resource_exhausted("throttling limit exceeded (<kind>)")
  .with_quota_violation("throttling", "<kind> limit exceeded")` with `kind ∈ {rate_limit, max_keys, in_flight}`.
  It sets `violations[0].retry_after_seconds`, a `Retry-After` header, and on rate-limit also `RateLimit-Policy`,
  `RateLimit-Limit`, `X-RateLimit-Limit`. The status is the zone's `response_status_code` (default 429).
  `resource_type = gts.cf.core.api_gateway.gateway.v1~`.
  On successful requests, `RateLimit-*` headers are added to the response.
* **In-flight permits are released when `next.run(req)` returns**, that is when the handler returns the
  response head. For an SSE response the permit does not cover the streaming phase.
* The OpenAPI vendor extensions are `x-throttling-rate-limit-zone` and `x-throttling-in-flight-limit-zone`
  (toolkit `openapi_registry.rs`). The gateway enriches them with `x-rate-limit-rps`, `x-rate-limit-burst` and `x-in-flight-limit`.

### 1.6 URL prefix handling

* A gear registers absolute paths: `"/mini-chat/v1/chats/{id}"`. Nothing prepends the gear name.
  types-registry uses consts `V1 = "/types-registry/v1"` with `format!("{V1}/entities")`.
* The gateway config `prefix_path` (default `""`), for example `"/cf`", is applied **after** the middleware stack:
  `Router::new().nest(prefix, router)` (`api-gateway/src/gear.rs` `apply_prefix`). Consequences:
  * In a handler, `axum::http::Uri` holds the path **without** the prefix (nest strips it).
    `axum::extract::OriginalUri` holds the full client path. types-registry
    `operation_location()` deliberately uses `OriginalUri`, because an absolute `Location` without the
    prefix gives the client a 404.
  * `Problem.instance` is the stripped path, because the canonical middleware is inside the nest.
  * Auth, license, MIME and throttling lookups use the unprefixed `OperationSpec.path` (`common::resolve_path`
    strips `NestedPath`).
  * The OpenAPI document gets `servers: [prefix]`.

### 1.7 Gateway middleware order (request path, outermost → innermost)

From `ApiGateway::apply_middleware_stack`:
`SetRequestId (x-request-id generated if absent)` → `PropagateRequestId` → `Trace` → `push_req_id` →
`access_log` → `http_metrics` → `canonical_error_middleware` → `CatchPanic` → `Timeout 30s (→504)` →
`RequestBodyLimitLayer + DefaultBodyLimit (defaults.body_limit_bytes, default 16 MiB)` → `CORS` →
`MIME validation` → `pre-auth throttling` → `error_mapping (no-op)` → `[internal auth]` → `AuthN` →
`[scope enforcement]` → `post-auth throttling` → `license validation` → routes (+ `propagate_matched_path`
route_layer). After this, the stack is nested under `prefix_path`.

Gear rule (docs `04_rest_operation_builder.md`): do **not** add CORS, timeout, compression or body-limit layers in the gear.

MIME validation (`middleware/mime_validation.rs`) runs only when `allowed_request_content_types` is set
(by `multipart_file_request`, `octet_stream_request` or `allow_content_types`). On failure it returns **400**
`invalid_argument`, `field_violations[0] = {field: "content-type", reason: "UNSUPPORTED_MEDIA_TYPE" | "MISSING_CONTENT_TYPE"}`,
`resource_type = gts.cf.core.api_gateway.gateway.v1~`. It never returns 415. The 415 status comes only from the JSON extractor.

### 1.8 Handler signatures and extractors

Prelude (`libs/toolkit/src/api/mod.rs`):

```rust
pub mod canonical_prelude {
    pub use toolkit_canonical_errors::{CanonicalError, Problem, resource_error};
    pub type ApiResult<T = ()> = std::result::Result<T, CanonicalError>;
    pub use super::odata::OData;
    pub use super::response::{JsonBody, JsonPage, created_json, no_content, ok_json};
    pub use super::rest::extract;            // extract::{Json, Path, Query}  (canonical rejections)
    pub use super::select::apply_select;
    pub use axum::{Json, http::StatusCode, response::IntoResponse};   // NOTE: plain axum::Json
}
```

With `use toolkit::api::canonical_prelude::*;`, the name `Json` is **`axum::Json`**, which is fine as a response
body. For request bodies, write `extract::Json<T>` (types-registry does this:
`extract::Json(req): extract::Json<SubmitEntitiesRequest>`). Alternatively import
`toolkit::api::rest::extract::{Json, Path, Query}` directly. That `Json` also implements `IntoResponse`.

Handler examples (credstore `api/rest/handlers.rs`):

```rust
use axum::extract::Extension;
use toolkit::api::canonical_prelude::*;
use toolkit_security::SecurityContext;

pub async fn create_secret(
    uri: axum::http::Uri,
    Extension(ctx): Extension<SecurityContext>,
    Extension(svc): Extension<Arc<ConcreteService>>,
    Json(body): Json<CreateSecretRequestDto>,          // (credstore uses axum::Json here -> see 1.9)
) -> ApiResult<impl IntoResponse> {
    // ...
    svc.put(&ctx, &key, /*...*/).await?;               // `?` via impl From<DomainError> for CanonicalError
    let location = format!("{}/{}", uri.path().trim_end_matches('/'), key.as_ref());
    Ok((StatusCode::CREATED, [(axum::http::header::LOCATION, location)]).into_response())
}

pub async fn put_secret(
    Extension(ctx): Extension<SecurityContext>,
    Extension(svc): Extension<Arc<ConcreteService>>,
    Path(reference): Path<String>,
    headers: axum::http::HeaderMap,
    Json(body): Json<UpdateSecretRequestDto>,
) -> ApiResult<impl IntoResponse> { /* ... */ Ok(StatusCode::NO_CONTENT.into_response()) }
```

Extractor order follows axum: `FromRequestParts` extractors (`Extension`, `Path`, `Query`, `OData`,
`HeaderMap`, `Uri`, `OriginalUri`) come first, then at most one body extractor last (`Json`,
`axum::extract::Multipart`, `axum::body::Body`, `axum::extract::Request`, `Bytes`).

Alternative style (oagw): `Result<impl IntoResponse, Box<Problem>>`. `Box<Problem>` implements `IntoResponse`.
For new code prefer `ApiResult` / `CanonicalError`.

### 1.9 Platform JSON / Path / Query extractors (exact behaviour)

File: `libs/toolkit/src/api/rest/extract/{json,path,query,error}.rs`. Each one delegates to axum and
maps the rejection through `rejection_to_canonical(field, code, status, message)`:

```rust
GenericResourceError::invalid_argument()          // #[resource_error(gts_id!("cf.core.http.request.v1~"))]
    .with_field_violation(field, truncate_description(message) /*≤500 chars*/, code)
    .with_override(Http::status_code(status))     // keeps axum's status
    .create()
// status >= 500 -> CanonicalError::internal(message) instead (route/type bugs, e.g. Path arity mismatch)
```

| Extractor | axum rejection | HTTP | `field` | `reason` |
|---|---|---|---|---|

### 1.10 Multipart / raw body for streaming uploads

* OpenAPI: `.multipart_file_request("file", Some("File to upload"))` produces `multipart/form-data`
  `{type:object, properties:{file:{type:string, format:binary}}, required:[file]}` and the description
  `"File to upload (expects field 'file' with file data)"`, which is exactly the api.json `upload_attachment` body. It
  also enables gateway MIME validation (400 when the type is not `multipart/form-data`).
* No gear in the repo has a multipart *request* handler. toolkit has no helper:
  `toolkit::http::multipart::MultipartJsonStream` is a `multipart/mixed` **response** framer.
* Options:
  * `axum::extract::Multipart` (axum feature `multipart`, enabled in mini-chat). Its `MultipartRejection`
    is `text/plain`, so the gateway wraps it as `about:blank`. To get the reasons the ADR expects
    (`BOUNDARY_REQUIRED`, `MULTIPART_ERROR`, `MISSING_FILE`, `MISSING_CONTENT_TYPE`), parse it yourself.
  * Raw streaming with `multer` 3.1 (already a mini-chat dependency). The API was checked in the
    `multer-3.1.0` source:

```rust
// composed example
pub async fn upload_attachment(
    Extension(ctx): Extension<SecurityContext>,
    Extension(svc): Extension<Arc<AppServices>>,
    extract::Path(chat_id): extract::Path<uuid::Uuid>,
    headers: axum::http::HeaderMap,
    body: axum::body::Body,                                  // last extractor; not buffered
) -> ApiResult<impl IntoResponse> {
    let ct = headers.get(axum::http::header::CONTENT_TYPE).and_then(|v| v.to_str().ok()).unwrap_or("");
    let boundary = multer::parse_boundary(ct).map_err(|_|
        AttachmentResource::invalid_argument()
            .with_field_violation("content_type", "multipart boundary is required", "BOUNDARY_REQUIRED")
            .create())?;
    let mut mp = multer::Multipart::new(body.into_data_stream(), boundary);
    // optional: multer::Multipart::with_constraints(stream, boundary,
    //     multer::Constraints::new().size_limit(multer::SizeLimit::new().per_field(max_bytes)))
    while let Some(mut field) = mp.next_field().await.map_err(|e| /* MULTIPART_ERROR */ ...)? {
        if field.name() != Some("file") { continue; }
        let filename = field.file_name().map(str::to_owned);
        let mime = field.content_type().cloned();             // Option<mime::Mime>
        while let Some(chunk) = field.chunk().await.map_err(/* MULTIPART_ERROR */ ...)? {
            // stream chunk (bytes::Bytes) to provider / size accounting
        }
    }
    // ...
}
```

  Body size: the gateway `RequestBodyLimitLayer::new(defaults.body_limit_bytes)` returns a 413
  `text/plain`, which becomes an `about:blank` 413 problem, before the handler runs when `Content-Length`
  is too large. Otherwise the limited body yields an error while it streams. `DefaultBodyLimit` affects only
  axum's buffering extractors (`Json`, `Bytes`, `Multipart`), not `Body::into_data_stream()`.
  `config/mini-chat.yaml` sets `defaults.body_limit_bytes: 64000000`.
* `octet_stream_request(Some(desc))` is for a raw `application/octet-stream` body (schema `string/binary`).
* oagw's proxy handler (`gears/system/oagw/oagw/src/api/rest/handlers/proxy.rs`) is the in-repo example of
  taking `req: axum::extract::Request` and `req.into_parts()`.

## 2. Canonical errors (RFC 9457 `Problem`)

Crate `cf-gears-toolkit-canonical-errors` (lib `toolkit_canonical_errors`). Features: `axum`
(IntoResponse impls), `utoipa` (Problem schema), `sea-orm` (`From<DbErr>` → internal), `debug-problem`.
Re-exports: `CanonicalError, Problem, ProblemCategory, ResourceErrorBuilder, ServiceUnavailableBuilder,
FieldViolation, QuotaViolation, PreconditionViolation, Http, TransportOverride, ForeignPassthrough,
resource_error (attr macro), gts_id (macro)` and the context structs (`NotFound`, `InvalidArgument`, ...).

### 2.1 Declaring a gear's resource types (`toolkit-canonical-errors-macro`)

```rust
use toolkit_canonical_errors::{CanonicalError, resource_error};

#[resource_error(gts_id!("cf.core.mini_chat.chat.v1~"))]       pub struct ChatResource;
#[resource_error(gts_id!("cf.core.mini_chat.message.v1~"))]    pub struct MessageResource;
#[resource_error(gts_id!("cf.core.mini_chat.turn.v1~"))]       pub struct TurnResource;
#[resource_error(gts_id!("cf.core.mini_chat.attachment.v1~"))] pub struct AttachmentResource;
#[resource_error(gts_id!("cf.core.mini_chat.model.v1~"))]      pub struct ModelResource;
```

(Resource ids from mini-chat ADR-0004 / DESIGN §: `gts.cf.core.mini_chat.{chat,message,turn,attachment,model}.v1~`.)
Rules enforced at compile time (`libs/toolkit-canonical-errors-macro/src/lib.rs`):

* The argument is either a full string literal `"gts.cf...v1~"` or `gts_id!("cf....v1~")`. The `gts.` prefix
  is added from the build-time `GTS_ID_PREFIX`. The id must parse as a GTS **type** id (ends with `~`).
* The struct must be a non-generic unit struct. The crate `cf-gears-toolkit-canonical-errors` must be a
  direct dependency (it is: `toolkit-canonical-errors = { workspace = true, features = ["axum"] }`).

Generated associated fns (visibility = struct visibility). The typestate shows what you must call before
`.create()`:

| Fn | Category / HTTP | Default `detail` | Resource name | Required before `.create()` |
|---|---|---|---|---|
| `not_found(detail)` | not_found / 404 | arg | **required** `.with_resource(name)` | — |
| `already_exists(detail)` | already_exists / 409 | arg | **required** | — |
| `data_loss(detail)` | data_loss / 500 | arg | **required** | — |
| `aborted(detail)` | aborted / 409 | arg | optional | **`.with_reason(r)`** |
| `unknown(detail)` | unknown / 500 | arg | optional | — |
| `deadline_exceeded(detail)` | deadline_exceeded / 504 | arg | optional | — |
| `permission_denied()` | permission_denied / 403 | "You do not have permission to perform this operation" | not allowed | **`.with_reason(r)`** |
| `unimplemented(detail)` | unimplemented / 501 | arg | optional | — |
| `cancelled()` | cancelled / 499 | "Operation cancelled by the client" | not allowed | — |
| `invalid_argument()` | invalid_argument / 400 | "Request validation failed" | optional | **`.with_field_violation(field, description, reason)`** (repeatable) **or** `.with_format(msg)` **or** `.with_constraint(msg)` (these two set detail=msg) |
| `out_of_range(detail)` | out_of_range / 400 | arg | optional | **`.with_field_violation(..)`** |
| `resource_exhausted(detail)` | resource_exhausted / 429 | arg | optional | **`.with_quota_violation(subject, description)`** (repeatable), optional `.with_quota_violation_retry_after_seconds(u64)` (applies to the last violation) |
| `failed_precondition()` | failed_precondition / 400 | "Operation precondition not met" | optional | **`.with_precondition_violation(subject, description, type_)`** (repeatable) |

Arguments are in the order `(field, description, reason)` for field violations and `(subject, description, type_)` for precondition
violations. The wire order of keys is `{type, subject, description}`.

Top-level constructors (no resource type):

```rust
CanonicalError::internal(diagnostic).create()                 // 500, wire detail is ALWAYS
                                                              // "An internal error occurred. Please retry later.";
                                                              // the arg goes to ctx.description (#[serde(skip)]), logged by middleware
CanonicalError::service_unavailable()                         // 503, detail "Service temporarily unavailable"
    .with_retry_after_seconds(5)                              // -> context.retry_after_seconds + Retry-After header
    .with_detail("...")
    .create()
CanonicalError::unauthenticated().with_reason("TOKEN_EXPIRED").create()  // 401, detail "Authentication required"
```

Any builder can call `.with_override(toolkit_canonical_errors::Http::status_code(422))` to change only the HTTP
status. It must stay in the same status class: a `debug_assert!` rejects e.g. invalid_argument→500.
`Http::status_code` is `const fn`, so a named constant is possible:
`pub const GONE: TransportOverride = Http::status_code(410);`.

Accessors on `CanonicalError`: `status_code() -> u16`, `gts_type() -> &'static str`, `title()`,
`detail()`, `resource_type()`, `resource_name()`, `diagnostic()` (internal/unknown only),
`http_status_override()`. `Display` prints `"<category>: <detail>"`.

Built-in conversions: `From<std::io::Error>` gives internal. `From<serde_json::Error>` gives
invalid_argument with a `format` context. `From<sea_orm::DbErr>` (feature `sea-orm`) gives internal.
`From<toolkit_odata::Error>` is in toolkit-odata `problem_mapping.rs`.

### 2.4 Conversion to axum responses

* `impl IntoResponse for CanonicalError` (feature `axum`) does `Problem::from(self).into_response()`, then stores
  a clone of the `CanonicalError` in the response extensions so the middleware can log `diagnostic()`.
* `impl IntoResponse for Problem`: status from `problem.status`, `Content-Type: application/problem+json`,
  and **`Retry-After: <n>` only when the category is `service_unavailable` and `context.retry_after_seconds` is
  set**. A `resource_exhausted` error's `violations[].retry_after_seconds` does not produce a header.
  Add one yourself when needed:
  ```rust
  let mut resp = err.into_response();
  resp.headers_mut().insert(axum::http::header::RETRY_AFTER, axum::http::HeaderValue::from(secs));
  ```
  The canonical middleware preserves `Retry-After`, `RateLimit-*` and `X-RateLimit-*` (`PRESERVED_*` lists).
* `toolkit::api::canonical_error_middleware` (`libs/toolkit/src/api/canonical_error_layer.rs`), installed by
  the gateway:
  * Responses with the `ForeignPassthrough` extension are untouched.
  * An `application/problem+json` response is read (2 s / 64 KiB budget). It fills `instance = request path`
    if missing, and `trace_id` if missing. `trace_id` is taken in this order: W3C `traceparent` trace-id
    segment, then `x-trace-id`, then `x-request-id`, then the current span id. The gateway always generates
    `x-request-id`. It then sets `status` and recomputes `Content-Length`. It logs `warn!` for 4xx and
    `error!` for 5xx, with the diagnostic.
  * Any other 4xx/5xx with no `Content-Type` or with `text/plain` is wrapped. A 4xx becomes
    `{type:"about:blank", title:reason, detail:reason, ...}`. A 5xx becomes the `internal` category.
  * 2xx/3xx and non-problem typed bodies (JSON, HTML, **`text/event-stream`**) pass through **without being read**.
* Recommended per-gear mapping (credstore `infra/sdk_error_mapping.rs`, types-registry `api/rest/error.rs`):
  ```rust
  impl From<DomainError> for CanonicalError {
      fn from(err: DomainError) -> Self {
          match err {
              DomainError::ChatNotFound { id } => ChatResource::not_found("Chat not found")
                  .with_resource(id.to_string()).create(),
              DomainError::TurnAlreadyRunning => ChatResource::aborted("Another turn is running")
                  .with_reason("turn_already_running").create(),
              DomainError::InvalidTitle(msg) => ChatResource::invalid_argument()
                  .with_field_violation("title", msg, "INVALID_TITLE").create(),
              DomainError::AttachmentLocked => AttachmentResource::already_exists("Attachment is referenced")
                  .with_resource("attachment_locked").create(),
              DomainError::QuotaExceeded { scope } => ChatResource::resource_exhausted("Quota exceeded")
                  .with_quota_violation(scope, "quota_exceeded").create(),
              DomainError::TurnNotTerminal => TurnResource::failed_precondition()
                  .with_precondition_violation("turn_state", "Turn is not terminal", "STATE").create(),
              DomainError::PdpUnavailable => CanonicalError::service_unavailable()
                  .with_retry_after_seconds(5).create(),
              DomainError::Internal(e) => CanonicalError::internal(e.to_string()).create(),
          }
      }
  }
  ```
  Handlers then return `ApiResult<...>` and use `svc.op(...).await?`. In a handler,
  `.map_err(CanonicalError::from)?` is sometimes needed to help inference (credstore does this).

## 3. OData (`$filter`, `$orderby`, `$select`, `limit`/`$top`, `cursor`/`$skiptoken`)

### 3.1 Extractor (`libs/toolkit/src/api/odata.rs`)

```rust
use toolkit::api::odata::OData;             // also in canonical_prelude
pub async fn list_chats(
    Extension(ctx): Extension<SecurityContext>,
    Extension(svc): Extension<Arc<AppServices>>,
    OData(query): OData,                     // toolkit_odata::ODataQuery
) -> ApiResult<Json<toolkit_odata::Page<ChatDetailDto>>> { ... }
```

`OData` derefs to `ODataQuery`. There is also `pub async fn extract_odata_query<S>(parts:&mut Parts, state:&S) -> Result<ODataQuery, CanonicalError>`,
which types-registry calls from its own `FromRequestParts` impl.

The wire binding is `ODataParams`: `$filter`, `$orderby`, `$select`, `limit` (alias `$top`), and `cursor`
(alias `$skiptoken`). Sending both spellings gives a serde duplicate error, which is an `INVALID_QUERY_PARAMS` 400.

Steps, in order:
1. Every `$`-prefixed key outside `ACCEPTED_SYSTEM_QUERY_OPTIONS = ["$filter","$orderby","$select","$top","$skiptoken"]`
   is rejected. All offenders are reported in one response, each with reason `UNSUPPORTED_QUERY_PARAM` and the
   key as `field`. Bindings are case-sensitive: `$Top` gives "binds only as `$top`".
   Unprefixed unknown keys (`?foo=1`) are **ignored**; a gear needs its own guard to reject them.
2. `$filter`: when trimmed length > `MAX_FILTER_LEN` (8192) → `FILTER_TOO_LONG`. A parse error →
   `INVALID_FILTER`. More than `MAX_NODES` (2000) nodes → `FILTER_TOO_COMPLEX`. On success, the
   filter hash is computed (`short_filter_hash`) and stored in `query.filter_hash`.
3. `cursor` together with `$orderby` → `ORDER_WITH_CURSOR`, reported twice (fields `$orderby` and `cursor`).
4. `cursor` → `CursorV1::decode`. Failure → `INVALID_CURSOR`, and the order is left empty (it is taken from the cursor later).
   Otherwise `$orderby` → `parse_orderby` (`"f1 [asc|desc], f2 ..."`, max 1024 chars, max 10 keys, default asc)
   → `INVALID_ORDERBY_FIELD` on syntax errors. **Field names are validated later, by the paginator.**
5. `limit == 0` → `INVALID_LIMIT` with field `$top`. There is **no default and no upper clamp here**:
   `query.limit` is `None` when absent. The default and clamp come from `LimitCfg` in the paginator (§3.4).
6. `$select` → `parse_select` (lower-cased, max 2048 chars, max 100 fields, no duplicates, not empty) →
   `INVALID_SELECT` with field `$select`. Field names are not checked against the DTO.

Every extractor error uses `OdataError::invalid_argument()`
(`#[resource_error(gts_id!("cf.core.odata.query.v1~"))] pub struct OdataError;` in
`libs/toolkit-odata/src/errors.rs`). So the response is `400`, `context.resource_type = "gts.cf.core.odata.query.v1~"`.
An axum query-deserialize failure (e.g. `limit=abc`) gives `field: "query"`, reason `INVALID_QUERY_PARAMS`.

`toolkit_odata::Error` → `CanonicalError` (`libs/toolkit-odata/src/problem_mapping.rs`). The same mapping applies to
errors returned by the paginator, so the repository can `?` them into `CanonicalError`:

| `toolkit_odata::Error` | field | reason | description |
|---|---|---|---|
| `InvalidFilter(msg)` | `$filter` | `INVALID_FILTER` | `Invalid $filter: {msg}` |
| `InvalidOrderByField(f)` | `$orderby` | `INVALID_ORDERBY_FIELD` | `Unsupported $orderby field: {f}` |
| `InvalidCursor`, `CursorInvalidBase64/Json/Version/Keys/Fields/Direction` | `cursor` | `INVALID_CURSOR` | `invalid cursor[: ...]` |
| `OrderMismatch` | `cursor` | `ORDER_MISMATCH` | Order mismatch between cursor and query |
| `FilterMismatch` | `cursor` | `FILTER_MISMATCH` | Filter mismatch between cursor and query |
| `InvalidLimit` | `$top` | `INVALID_LIMIT` | Invalid page size parameter ($top, alias limit) |
| `OrderWithCursor` | `$orderby` + `cursor` | `ORDER_WITH_CURSOR` | two violations |
| `Db(msg)`, `ParsingUnavailable` | — | internal 500 | diagnostic only |

Extractor-only reasons: `FILTER_TOO_LONG`, `FILTER_TOO_COMPLEX`, `INVALID_SELECT`, `UNSUPPORTED_QUERY_PARAM`,
`INVALID_QUERY_PARAMS`. In code they are `toolkit::api::odata::{MAX_FILTER_LEN, MAX_NODES, MAX_ORDERBY_LEN, MAX_ORDER_FIELDS, MAX_SELECT_LEN, MAX_SELECT_FIELDS, ACCEPTED_SYSTEM_QUERY_OPTIONS}`.

`ODataQuery` (pub fields): `filter: Option<Box<ast::Expr>>`, `order: ODataOrderBy`, `limit: Option<u64>`,
`cursor: Option<CursorV1>`, `filter_hash: Option<String>`, `select: Option<Vec<String>>`. Methods:
`filter()`, `has_filter()`, `has_select()`, `selected_fields() -> Option<&[String]>`, and the builders `with_*`.
`CursorV1 { k: Vec<String>, o: SortDir, s: String /*signed order "+f,-id"*/, f: Option<String> /*filter hash*/, d: "fwd"|"bwd" }`.
It is encoded as base64url (no padding) of `{"v":1,"k":[..],"o":"asc|desc","s":"..","f":"..","d":"fwd"}`.

### 3.2 Whitelisting fields: `FilterField`

```rust
// toolkit_odata::filter
pub enum FieldKind { String, I64, F64, Bool, Uuid, DateTimeUtc, Date, Time, Decimal }
pub trait FilterField: Copy + Eq + Hash + Debug + 'static {
    const FIELDS: &'static [Self];
    fn name(&self) -> &'static str;
    fn kind(&self) -> FieldKind;
    fn nullable(&self) -> bool { false }        // opt-in `eq null`/`ne null`
    fn from_name(name: &str) -> Option<Self>;   // provided
}
```

Operators per kind (`FieldKind::allows`). `with_odata_filter` publishes this exact table:

| Kind | Allowed ops |
|---|---|
| String | eq, ne, contains, startswith, endswith, in |
| Uuid | eq, ne, in |
| Bool | eq, ne |
| I64, F64, Decimal, DateTimeUtc, Date, Time | eq, ne, gt, ge, lt, le, in |

These match the published api.json: `list_chats` `x-odata-filter` = `{id:[eq,ne,in], title:[eq,ne,contains,startswith,endswith,in], updated_at:[eq,ne,gt,ge,lt,le,in]}`
(so id is Uuid, title is String, updated_at is DateTimeUtc). `list_messages` = `{created_at: DateTimeUtc, id: Uuid, role: String}`.

### 3.3 `#[derive(ODataFilterable)]` (crate `toolkit-odata-macros`)

```rust

// generates:
// #[derive(Copy, Clone, Debug, Eq, PartialEq, Hash)] pub enum ChatDetailDtoFilterField { Id, Title, UpdatedAt }
// impl ::toolkit_odata::filter::FilterField for ChatDetailDtoFilterField {
//     const FIELDS = [Id, Title, UpdatedAt]; fn name() -> "id"|"title"|"updated_at"; fn kind() -> FieldKind::...
```

* The enum is named `<Struct>FilterField`. Variants are UpperCamelCase field names. The wire name is the Rust field name.
  The kind string must name a `FieldKind` variant. At least one field must be annotated.
  The macro does not check the Rust field type.
* The generated code refers to `::toolkit_odata`, which mini-chat already has as a direct dependency.
* The macro does not generate `nullable()`. For nullable fields, implement `FilterField` by hand (example:

* The order of `FIELDS` sets the order of published orderby options (`updated_at asc/desc, id asc/desc, title asc/desc` in api.json).
  So the published `list_chats` order corresponds to a struct field order (or hand-written FIELDS) of `updated_at, id, title`.

### 3.4 Pagination with SeaORM: `paginate_odata`

`libs/toolkit-db/src/odata/sea_orm_filter.rs`. Re-exported at `toolkit_db::odata::{paginate_odata, LimitCfg, FieldToColumn, ODataFieldMapping, ...}`:

```rust
pub trait FieldToColumn<F: FilterField> {
    type Column: Clone + sea_orm::Iden + sea_orm::ColumnTrait + sea_orm::IntoSimpleExpr + 'static;
    fn map_field(field: F) -> Self::Column;
    // optional: value normalisation hook (default identity)
    fn is_orderable(_field: F) -> bool { true }
}
pub trait ODataFieldMapping<F: FilterField>: FieldToColumn<F> {
    type Entity: EntityTrait;
    fn extract_cursor_value(model: &<Self::Entity as EntityTrait>::Model, field: F) -> sea_orm::Value;
    fn cursor_kind(field: F) -> FieldKind { field.kind() }
}
#[derive(Clone, Copy)] pub struct LimitCfg { pub default: u64, pub max: u64 }

pub async fn paginate_odata<F, M, E, D, Mapper, C>(
    select: SecureSelect<E, Scoped>,          // already security-scoped
    conn: &C,                                 // C: DBRunner (SecureConn / SecureTx)
    query: &toolkit_odata::ODataQuery,
    tiebreaker: (&str, SortDir),              // e.g. ("id", SortDir::Desc) -- MUST be an F field name
    limit_cfg: LimitCfg,
    model_to_domain: Mapper,                  // Fn(E::Model) -> D
) -> Result<Page<D>, toolkit_odata::Error>
where F: FilterField, M: ODataFieldMapping<F, Entity = E>, E: EntityTrait, C: DBRunner;

pub async fn paginate_odata_try<..., MapErr, C>(...) -> Result<Page<D>, PaginateOdataTryError<MapErr>>
// PaginateOdataTryError::{OData(toolkit_odata::Error), MapError(MapErr)}
```

Semantics (`paginate_odata_collect`):
* `limit = clamp_limit(query.limit, cfg)`. The value is `req.unwrap_or(cfg.default)`, then 0 becomes 1, and anything above `cfg.max` becomes `max`. **It is clamped silently.**
  `page_info.limit` reports the clamped value. Mini-chat ADR: "A `limit` above 100 is clamped to 100", so use `LimitCfg{ default: <N>, max: 100 }`.
* Effective order: with a cursor, it is the cursor's `s`. Otherwise it is `query.order.ensure_tiebreaker(tiebreaker)`. Each key must be
  `F::from_name(..)` and `M::is_orderable(..)`, otherwise `InvalidOrderByField`. This is where an unknown `$orderby` field is rejected.
* A cursor with a filter hash requires the same filter (`query.filter_hash`), otherwise `FilterMismatch`.
* `$filter` AST → `convert_expr_to_filter_node::<F>`. Unknown fields, ops not allowed for the kind, and type mismatches all give `InvalidFilter`.
  The condition is built by `filter_node_to_condition::<F, M>`.
* It fetches `limit + 1` rows to detect `has_more`. It builds `next_cursor` (from the last row, `d:"fwd"`) when `has_more` or when paging backward.
  It builds `prev_cursor` (from the first row, `d:"bwd"`) when a cursor was supplied. Backward pages are reversed back into the requested order.
* A DB error gives `Error::Db` → internal 500.
* Cursor value encoding by kind (`encode_cursor_value`): `DateTimeUtc` accepts both `ChronoDateTimeUtc` and
  `TimeDateTimeWithTimeZone` (formatted `YYYY-MM-DDTHH:MM:SS.nnnnnnnnnZ`). `Uuid` → `Value::Uuid`, `String` → `Value::String`,
  `I64` → `BigInt/Int/SmallInt`.
  ⚠ `$filter` datetime literals are bound as `sea_orm::Value::ChronoDateTimeUtc` (`sea_orm_filter.rs:340`). If the
  mini-chat columns are `time::OffsetDateTime` on SQLite (TEXT storage), add a test that a `updated_at gt ...` filter compares correctly.

Mapper (pattern from `libs/toolkit-db/tests/odata_null_like.rs` and the `sea_orm_filter.rs` docs):

### 4.1 Existing SSE code in the repo

* **axum native** (`axum 0.8.9`): `axum::response::sse::{Sse, Event, KeepAlive}`. `Sse::new(stream)` sets
  `Content-Type: text/event-stream` and `Cache-Control: no-cache`. `KeepAlive::new()` defaults to a 15 s interval
  and sends an empty comment (`:\n\n`). Customize with `.interval(d)`, `.text("...")`, `.event(Event)`.
  `Event::default().event("delta").data(s)`, `.json_data(&T) -> Result<Event, axum::Error>`, `.id(..)`, `.retry(Duration)`, `.comment(..)`.
* **`toolkit::SseBroadcaster<T>`** (`libs/toolkit/src/http/sse.rs`, re-exported at `toolkit::SseBroadcaster`) is a
  `tokio::sync::broadcast` fan-out. Methods: `new(capacity)`, `send(T)`, `subscribe_stream()`,
  `sse_response()`, `sse_response_named(name)`, `sse_response_with_headers(headers)`, `sse_response_named_with_headers(..)`.
  All of them use `KeepAlive::new().interval(15s).text("keepalive")` and JSON `data`. On a lagging subscriber,
  events are **dropped**. It fits pub/sub feeds. It does not fit a per-request LLM stream, where you should build your own `Stream`.
* **oagw-sdk** (`gears/system/oagw/oagw-sdk/src/sse/`): a client-side parser for upstream SSE
  (`ServerEventsStream`, `ServerEvent{id,event,data,retry}`, `is_server_events_response`). It also has a server helper

  which sets `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive` and
  **`X-Accel-Buffering: no`** (to disable nginx-style proxy buffering).
* Test handler shape (`libs/toolkit-contract/tests/rest_client_codegen.rs`):

### 4.2 Recommended handler shape for `POST /mini-chat/v1/chats/{id}/messages:stream`

```rust
// composed example
use axum::response::{IntoResponse, Response, sse::{Event, KeepAlive, Sse}};

pub async fn stream_message(
    Extension(ctx): Extension<SecurityContext>,
    Extension(svc): Extension<Arc<AppServices>>,
    extract::Path(chat_id): extract::Path<uuid::Uuid>,
    extract::Json(req): extract::Json<StreamMessageRequest>,
) -> ApiResult<Response> {
    // Everything awaited here counts toward the 30 s gateway timeout and may still fail with a Problem.
    let events = svc.start_stream(&ctx, chat_id, req).await?;   // -> impl Stream<Item = StreamEvent>
    let sse = events.map(|ev| Ok::<_, std::convert::Infallible>(ev.into_sse_event()));
    let mut resp = Sse::new(sse)
        .keep_alive(KeepAlive::new().interval(std::time::Duration::from_secs(15)))
        .into_response();
    resp.headers_mut().insert("x-accel-buffering", axum::http::HeaderValue::from_static("no"));
    Ok(resp)
}
```

### 4.3 Gateway behaviour for streams

* **Compression:** none. There is no `tower_http::compression` in the workspace (the only hits are client-side
  *decompression* in `toolkit-http`). Nothing needs to be disabled. `X-Accel-Buffering: no` and
  `Cache-Control: no-cache` matter only for external reverse proxies.
* **Buffering:** none for 2xx. `access_log_middleware` wraps the body in `CountingBody`, a streaming pass-through
  that logs `bytes_sent` when the body ends. `canonical_error_middleware` does not read non-problem bodies.
  `http_metrics`, `TraceLayer` and the throttling layer work on the response head only.
* **30 s timeout:** `ServiceBuilder::new().layer(HandleErrorLayer::new(timeout_to_canonical)).timeout(Duration::from_secs(30))`
  (`api-gateway/src/gear.rs`). `tower::timeout` wraps the service future that produces the `Response`, so it
  stops counting once the handler returns `Sse`. The SSE body can stream for any length of time. There is no
  route-level exemption mechanism, and none is needed. What must finish in under 30 s is all handler work before
  `return` (auth, PDP, DB inserts, provider connect if awaited). The mini-chat DESIGN therefore does the setup and returns the stream promptly.
  If the head is late, the client gets 504 `deadline_exceeded`.
  The only explicitly un-timed path is the gateway's OoP reverse-proxy client (`HttpClientConfig::proxy()`),
  per the comment "no 30s request timeout (SSE / streaming upstreams stay open)".
* **In-flight limit:** the permit is dropped when the head is returned (§1.5), not when the stream ends.
* **Client disconnect:** hyper drops the response body, which drops your stream. Detect it with a drop guard or a
  `CancellationToken` tied to the stream's lifetime.
* **Errors after the head:** the status is already 200, so no Problem is possible. Send a terminal
  `event: error` with `data: {code, message}` (mini-chat ADR-0004), then end the stream.

## 5. `Location` header on 201 and access to the request path

* Helper `toolkit::api::response::created_json` (also in `canonical_prelude`):

## 8. Pitfalls and stale docs (code verified)

1. `docs/toolkit_unified_system/04_rest_operation_builder.md` and `05_errors_rfc9457.md` contain stale content:
   * `toolkit::api::prelude` does not exist. Use `toolkit::api::canonical_prelude`.
   * `toolkit::api::problem::Problem` does not exist. Use `toolkit_canonical_errors::Problem`.
   * `binary_response` and `with_422_validation_error` do not exist. Use `error_422` or `with_400_validation_error`.
   * `Sse::new(stream, "name")` is not a valid call.
   * The docs say "standard_errors adds 422". The code does not add 422.
   * The docs show `ApiResult = Result<T, Problem>`. The real alias uses `CanonicalError`.
   * `odata_error_to_problem` does not exist.
   * `I32` is not a `FieldKind`.
2. The plain `Json` exported by `canonical_prelude` is `axum::Json`. Use `extract::Json` for request bodies, or you lose
   `missing_json_content_type`, `invalid_json_body` and `json_syntax_error`.
3. `require_license_features::<License>([])` registers **no** license requirement. Use `[&License]` to declare the base feature.
4. `Retry-After` is automatic only for `service_unavailable`.
5. The OData extractor does not default or clamp `limit`. `LimitCfg` in the paginator does both, silently.
   Unknown `$filter` and `$orderby` **fields** are rejected by the paginator, not the extractor. The rejection
   still uses `resource_type gts.cf.core.odata.query.v1~` once you convert it with `CanonicalError::from(odata_err)`.
6. A tiebreaker field must be part of the `FilterField` enum, otherwise every list fails with `INVALID_ORDERBY_FIELD`.
7. The gateway MIME validation returns 400 (`UNSUPPORTED_MEDIA_TYPE`), not 415. The 415 comes only from `extract::Json`.
8. For SSE: return the head quickly (under 30 s), do not rely on in-flight zones to bound stream concurrency, and send
   errors after the head as SSE `error` events.
9. Routes registered with raw `router.route(...)` (as oagw does for its proxy) are invisible to the OpenAPI document,
   throttling, license and MIME maps. Auth then falls back to `require_auth_by_default`.
